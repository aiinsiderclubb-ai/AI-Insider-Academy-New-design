# Как проверены воркфлоу

## Логика узлов Code — 12 сценариев

1. Сайт: без токена — отказ, пустое сообщение — отказ.
2. Вопрос из FAQ в разрешённой категории в режиме автоответа: бот отвечает, таблица получает заголовок и строку `answered`, в запросе к модели есть FAQ и запрет выполнять инструкции из обращения.
3. Тот же клиент продолжает то же обращение: строка обновляется, история растёт.
4. Режим черновиков: ничего не отправляется, команда получает черновик с кнопкой, сайт — «спасибо, ответим».
5. Недовольство, срочность, низкая уверенность, неразрешённая категория, запрещённая тема — каждое оставляет человека в контуре и называет причину.
6. Модель ответила не JSON: обращение уходит человеку без черновика.
7. Telegram: /start — приветствие; группы и разговоры в чате команды игнорируются.
8. Черновик из Telegram одобрен кнопкой: ответ уходит в чат клиента, в таблице `answered` и имя сотрудника; повторное нажатие ничего не отправляет; кнопка из чужого чата игнорируется.
9. Сотрудник отвечает ответом на сообщение бота; «Ответим сами» снимает черновик.
10. Почта: роботы, автоответы и свои письма пропускаются, цитата отрезается, тема получает «Re:».
11. Напоминания: одно по сроку, второе руководителю при двойной просрочке, ночью — ничего.
12. Сводка: доля ответов бота и список вопросов без ответа в FAQ.

## Запуск в n8n 2.44

Воркфлоу импортированы в n8n и вызваны по HTTP. Google Таблицы, модель, Telegram и почта заменены локальным сервером с теми же форматами запросов и ответов; триггеры Telegram и IMAP — вебхуками с тем же содержимым.

- Сайт без токена → 403.
- Вопрос из FAQ с сайта в режиме автоответа → ответ на странице, строка `answered`, уведомление команде.
- Письмо с цитатой → ответ письмом с темой «Re: Доставка», цитата не попала в обращение.
- Срочное сообщение в Telegram → черновик с кнопками в чате команды.
- Нажатие «Отправить» → ответ в чат клиента, имя сотрудника в таблице.
- Ответ сотрудника на сообщение бота по обращению с сайта → письмо клиенту.
- Telegram /start → приветствие.
- Вопрос вне FAQ → «ответьте сами» с причинами.
- Daily Digest → сводка со списком вопросов без ответа.

## Что не проверялось

- Настоящие Telegram, IMAP, SMTP и Google Таблицы под вашими учётными данными — проверьте по `test-requests.md`.
- Качество ответов конкретной модели по вашему FAQ — неделя в режиме черновиков.
