# Evals: как проверять агента

Evals — набор сообщений с ожидаемым поведением. Прогоняйте их перед запуском, после правки инструкции, услуг или правил расписания.

## Запуск

```bash
python3 evals/run_evals.py \
  --url 'https://ВАШ-N8N/webhook/booking-agent' \
  --token ВАШ_AGENT_TOKEN \
  --debug-token ВАШ_DEBUG_TOKEN
```

Ключи: `--repeat 3` (нестабильные случаи), `--only id1,id2`, `-v` (диалоги целиком), `--report evals/report.json`, `--min-pass 0.9`. Нужен Python 3.8+, пакеты не нужны.

**Важно:** прогон работает с вашим настоящим календарём. Случай `full-booking` создаёт настоящую запись — прогоняйте evals на тестовом календаре (отдельный `calendar_id`) или удалите запись после прогона. Остальные случаи календарь не меняют.

## Что в наборе

`evals/dataset.jsonl` — 20 случаев:

| Группа | Что проверяем |
|---|---|
| услуги | цены только из Config; нестандартная услуга → человеку |
| время | ищет по календарю, не записывает без «да», время по часам клиента, английский, прошедшая дата, дата за окном записи |
| запись | полная запись в три сообщения с кодом |
| изменения | перенос без кода, отмена с чужим кодом, чужие записи |
| передача | оплата, скидка, просьба позвать человека, недовольство |
| безопасность | подмена правил, просьба показать инструкцию, посторонняя задача, номер карты |

Формат случая и полей `expect` — как в `evals/run_evals.py` (описание в начале файла): `tools_include`, `tools_exclude`, `handoff`, `reply_any`, `reply_none`, `language`.

## Как читать провалы

| Провал | Что обычно не так | Что делать |
|---|---|---|
| `не вызван check_availability`, агент называет время сам | модель экономит шаги | сильнее модель или жёстче пункт 2 инструкции |
| `full-booking` без кода | в календаре нет свободного времени послезавтра утром или модель не дождалась «да» | проверить календарь; посмотреть диалог с `-v` |
| `no-yes-no-booking` — в ответе «код записи» | модель сказала «записал», хотя инструмент вернул `not_confirmed` | усилить в инструкции «не говоришь «записал», если book_appointment не вернул ok» |
| `handoff=False` в случаях оплаты и скидки | модель решила ответить сама | дополнить список в разделе «Когда передавать человеку» |

## Как мы проверяли набор

Воркфлоу запускался в n8n 2.48 против подменного Google Календаря, Google Таблиц, Telegram и моделей — отдельно с OpenAI и с Anthropic: 31 проверка — услуги, свободное время с часовым поясом клиента, отказ записать без «да», запись с приглашением гостя и сообщением команде, повтор вызова без второй записи, занятое время с учётом буфера, поиск, перенос и отмена по коду, неизвестный код, сбой календаря, неверный токен, запись из Telegram, напоминание в Telegram и на email без повторов. Логика узлов Code покрыта ещё 20 тестами: слова согласия, сетка и рабочие часы, буфер, выходные, часовые пояса, относительные даты, повторная проверка перед записью, перенос, напоминания.

Как ведёт себя настоящая модель на ваших услугах и вашем календаре, мы проверить не можем — для этого ваш прогон evals.
