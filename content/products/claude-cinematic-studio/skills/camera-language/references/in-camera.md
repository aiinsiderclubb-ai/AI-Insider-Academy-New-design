# Переходы камерой

Лучший переход — тот, который сделала камера, а не плагин. 2D-переходы из `src/layers/Transitions.tsx` (`Sequence2`: `whip`, `zoom`, `flash`, `fade`) — запасной вариант, когда два кадра живут в разных сценах. Если кадры можно поставить в одну 3D-сцену, переход делай движением камеры.

## Whip pan внутри сцены

Камера резко перебрасывается с одного объекта на другой за 0,25–0,35 с. Глаз видит смаз и сам «склеивает» два плана.

```tsx
import { track } from "../lib/curves";
import { handheld, lens, type CameraMove, type Vec3 } from "../three/camera";

// Объект A в [-3, 0, 0], объект B в [3, 0, 0]. Переброс за 0,3 с с центром на 4,0 с.
const whipAt = 4.0;
const a = whipAt - 0.15;
const b = whipAt + 0.15;
const whip: CameraMove = {
  // Перед перебросом — медленный дрейф к A, переброс на expoInOut, после — докат у B.
  position: track<Vec3>([[0, [-3.4, 0.35, 6.4]], [a, [-3, 0.3, 6], "silk"], [b, [3, 0.3, 6], "expoInOut"], [b + 1.5, [3.3, 0.3, 5.6], "silk"]]),
  target: track<Vec3>([[a, [-3, 0, 0]], [b, [3, 0, 0], "expoInOut"]]),
  fov: () => lens(50),
};

<Stage look={look} camera={handheld(whip, 0.02)} aberrationBoost={2}>…</Stage>
```

Позиция и прицел переходят на одной кривой и в одно время. Если прицел перескочит на кадре склейки раньше позиции, будет щелчок.

- Хроматическая аберрация `Stage` растёт со **скоростью перемещения** камеры (`cameraSpeed` считает изменение позиции). Чистый поворот на месте её не поднимет: делай whip со сдвигом позиции, как выше, или через короткую орбиту.
- Без смаза whip выглядит как дёрганая склейка. Рендери кадр ×4 по fps и сводит `grade-finish` (раздел ниже). В черновике хватит аберрации.
- Звук — короткий swish ровно на середину переброса (`cut-rhythm`, `sfx.py`).
- Направление whip в соседних переходах чередуй или держи одно на весь ролик, не случайно.

## Пролёт сквозь объект

Камера наезжает на объект (стекло, букву, кольцо) до момента, когда он заполняет кадр. В этот кадр — склейка на следующую сцену, которая начинается так же заполненной и «раскрывается».

```tsx
// Кадр A: наезд в стеклянное ядро
const pushIn = dolly({ start: 2.4, end: 3.2, from: [0, 0, 6], to: [0, 0, 1.1], ease: "expoIn", mmFrom: 50, mmTo: 35 });
// Кадр B начинается вплотную к своему объекту и отъезжает
const pullOut = dolly({ start: 3.2, end: 4.6, from: [0, 0, 1.2], to: [0, 0.3, 6.5], ease: "expoOut", mmFrom: 35, mmTo: 50 });

<Sequence2 at={3.2} kind="cut" a={<SceneA camera={pushIn} />} b={<SceneB camera={pullOut} />} />
```

Скорость камеры в последнем кадре A и в первом кадре B должна совпадать: `expoIn` разгоняет, `expoOut` стартует с той же высокой скорости. Добавь `Flash` на 2 кадра или `LightLeak`, если стык заметен.

## Склейка по движению (match move)

Два разных мира, но камера в обоих движется одинаково: в одну сторону, с одной скоростью, на одном объективе. Зритель воспринимает это как непрерывное движение.

- Конец кадра A и начало кадра B — одно направление (`from → to` с одинаковым вектором) и одна скорость в единицах в секунду.
- Тот же `mm` у обоих.
- Главный объект в той же точке кадра (например, в центре или на правой трети).
- Склейка на долю (`cut-rhythm`, `cutlist.py`).

Совпадение форм между футажами (match cut по силуэту) ищет `match_cut.py` в `cut-rhythm`.

## Монтаж ракурсами в одной сцене

`cutBetween` — несколько камер в одной сцене. Пример с ударом каждого слова на долю — `KineticSpot.tsx`. Правило 30°: соседние ракурсы отличаются хотя бы на 30° или в 1,5 раза по крупности.

## Когда всё-таки 2D-переход

`Sequence2` из `src/layers/Transitions.tsx`:

| kind | Что делает | Длительность |
|---|---|---|
| `cut` | Склейка на кадре — правильный выбор в 70 % случаев | — |
| `whip` | Обе сцены уезжают вбок с направленным размытием | 0,3–0,4 с |
| `zoom` | A «проваливается» в камеру с размытием и засветкой, B приходит из-за неё | 0,35–0,5 с |
| `flash` | Белый кадр на стыке (2 кадра) | — |
| `fade` | Через чёрное: смена времени или места | 0,5–1 с |

Обе сцены рендерятся только во время перекрытия, вне его — одна. Переход больше 0,6 с в динамичном ролике выглядит как слайд-шоу.

## Скорость и motion blur

Любое быстрое движение (whip, snap zoom, пролёт частиц) без размытия в движении выглядит компьютерным: кадры резкие, движение «стробит». Композиции рассчитаны в секундах, поэтому тот же ролик можно отрендерить с частотой ×4 и смешать кадры:

```bash
npx remotion render TechFilm out/techfilm@120.mp4 --props='{"fps":120}'
```

Дальше `grade-finish` (`finish.py`) смешивает каждые 4 кадра с выбранным углом затвора (180° — киношная норма) в 30 к/с. Пока идёт работа над движением, рендери черновики в 30 к/с и `--scale=0.5`.
