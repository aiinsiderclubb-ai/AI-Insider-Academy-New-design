# Разбор звонка с клиентом

Из расшифровки получается то, с чем можно идти писать предложение: проверенные факты, посчитанная цена проблемы и честная оценка, стоит ли тратить на клиента время.

## Режим 1. Разбор после звонка

1. **Прочитай расшифровку целиком.** Если это аудио без текста — попроси расшифровку.
2. **Выпиши факты** в таблицу: тема, что сказал клиент (дословная короткая цитата), цифра, если была. Темы: причина и срочность, процесс по шагам, объём, ошибки, прошлые попытки, системы, кто решает, бюджет, срок, критерий успеха.
   - Только то, что сказал клиент. Слова продавца — не факт.
   - Чего не прозвучало — «не сказано». Это самая полезная часть разбора: список того, что нужно выяснить.
3. **Посчитай цену проблемы** скриптом из папки скилла. Подставляй только цифры из расшифровки:

   ```bash
   python3 scripts/deal_math.py cost --tasks 300 --minutes 12 --hourly 15 \
     --errors 10 --error-cost 40 --lost 40 --conversion 10 --check 200
   ```

   Не хватает цифры — не подставляй «среднюю по рынку». Посчитай без неё и напиши, какой вопрос задать клиенту.
4. **Оцени готовность** по десяти критериям (0, 1 или 2), порядок фиксированный: боль, объём, повторяемость, цифра проблемы, лицо, принимающее решение, бюджет, срок, системы, прошлые попытки, следующий шаг.

   ```bash
   python3 scripts/deal_math.py score --answers 2,1,2,2,1,1,0,2,1,2
   ```

   Шкала оценок по каждому критерию — в таблице ниже. Оценку ставь по словам клиента; «не сказано» — это 0.
5. **Разбери возражения.** Найди в расшифровке сомнения клиента, даже невысказанные прямо. Для каждого — что за ним стоит и ответ из [references/objections.md](references/objections.md).
6. **Напиши письмо с итогами** по первому шаблону из [assets/follow-up-emails.md](assets/follow-up-emails.md): что услышали словами клиента, цифры, следующий шаг и дата. До 150 слов.
7. **Сохрани `call-debrief.md`:** факты, «не сказано», расчёт, оценка с рекомендацией, возражения, письмо, вопросы на следующий контакт.

## Шкала оценки

| Критерий | 0 | 1 | 2 |
|---|---|---|---|
| Боль | «Было бы неплохо» | Мешает, но терпят | Теряют деньги или клиентов |
| Объём | Меньше 20 задач в месяц | 20–200 | Больше 200 |
| Повторяемость | Каждый случай уникален | Есть типовые | 80% по одному правилу |
| Цифра проблемы | Не назвали | Оценка на глаз | Клиент подтвердил расчёт |
| Кто решает | Неизвестно | Известно, не на звонке | Был на звонке |
| Бюджет | Нет и не планируют | «Найдём, если убедите» | Заложен |
| Срок | Нет | «В этом году» | Есть дата |
| Системы | Всё вручную, доступа нет | Экспорт или частичный API | API и администратор |
| Прошлые попытки | Не думали | Пробовали сами | Платили за решение |
| Следующий шаг | «Напишите потом» | Попросили предложение | Назначена встреча |

## Режим 2. Подготовка к звонку

Когда просят подготовиться: узнай нишу и что известно о клиенте, выбери 10–12 вопросов из [references/question-bank.md](references/question-bank.md) под эту нишу, расставь по ходу звонка (рамка → контекст → процесс → цифры → люди и бюджет → следующий шаг) и добавь два вероятных возражения с ответами. Сохрани в `call-prep.md`.

## Правила

- Цитаты дословные и короткие. Не улучшай формулировки клиента.
- Не делай вывод «клиент готов купить», если оценка ниже 15: скажи, чего не хватает.
- Если по оценке клиент не готов — рекомендуй не писать предложение и предложи письмо с конкретной датой возврата. Это тоже результат.
- В письме клиенту нет внутренних оценок и слов «квалификация», «лид», «скоринг».
