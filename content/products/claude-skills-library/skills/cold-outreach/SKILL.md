# Холодный аутрич

Одно сообщение — один факт о получателе, одна мысль, один вопрос. Скилл пишет сообщения и не отправляет их: отправка всегда за человеком.

## Что нужно на входе

- Что продаёт пользователь и кому (если есть `offer.md` — возьми оттуда).
- Список лидов: файл CSV или таблица в сообщении. Минимум — компания и имя. Полезно: должность, сайт, заметка.
- Канал: почта, LinkedIn, мессенджер. По умолчанию — почта.
- Сколько шагов: по умолчанию первое письмо и два продолжения.

Чего нет — спроси одним сообщением. Без понимания, что продаём, не начинай.

## Порядок работы

1. **Найди факт для каждого лида.** Источники по порядку: заметка в списке → сайт компании (если есть доступ в интернет, открой главную и страницу контактов или вакансий) → должность и ниша. Типы фактов — в [references/first-lines.md](references/first-lines.md). Факт должен быть проверяемым. Не нашёл — пиши первую строку через нишу и пометь лид как «без личного факта», не выдумывай наблюдение.
2. **Выбери шаблон** под ситуацию: [references/email-templates.md](references/email-templates.md), [references/linkedin-templates.md](references/linkedin-templates.md), [references/dm-templates.md](references/dm-templates.md). Шаблон — каркас: перепиши своими словами под лида, не подставляй механически.
3. **Напиши шаги** по порядку из [references/sequence.md](references/sequence.md). Каждое продолжение понятно без предыдущих и добавляет новое, а не «напоминаю о письме».
4. **Собери `messages.json`:**

   ```json
   {"messages": [{"id": "sever-1", "lead": "Клиника Север", "channel": "email",
                  "step": 1, "subject": "…", "body": "…"}]}
   ```

   `channel`: `email`, `linkedin_note` (заявка в контакты, до 300 знаков), `linkedin`, `dm`.
5. **Проверь скриптом** из папки этого скилла:

   ```bash
   python3 scripts/lint_outreach.py messages.json
   ```

   Исправь все `error` и разберись с каждым `warning`. Запускай повторно, пока ошибок не останется. Если Python недоступен — проверь вручную по правилам ниже и скажи об этом.
6. **Отдай результат:** `outreach.md` для чтения (по лидам, шаг за шагом) и `outreach.csv` с колонками `lead, name, channel, step, day, subject, body` для загрузки в сервис рассылки. Отдельно перечисли лидов «без личного факта».

## Правила, которые проверяет скрипт

- Письмо: до 90 слов (больше 120 — ошибка), тема до 45 знаков, не заглавными.
- В первом письме нет ссылок.
- Один вопрос на сообщение; сообщение без вопроса — предупреждение.
- Нет незаполненных `[подстановок]` и `{{переменных}}`.
- Нет слов-триггеров спам-фильтров: «бесплатно», «гарантия», «срочно», «100%».
- Первая строка — о получателе, а не «меня зовут».
- Одинаковая первая строка у разных лидов — значит, персонализации нет.

## Чего не делать

- Не выдумывать факты о компании, общих знакомых, «видел ваше выступление».
- Не обещать результат в цифрах, которых пользователь не давал.
- Не писать людям, которые просили не писать; не предлагать обход отписки.
- Не слать вложения и не просить «15 минут» в первом письме — сначала вопрос, на который легко ответить.

## После отправки

Напомни пользователю метрики из [references/sequence.md](references/sequence.md): доля ответов ниже 3% — менять тему и первую строку; положительных ответов меньше трети — пишем не тем людям.
