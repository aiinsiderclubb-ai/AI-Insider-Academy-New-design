# Проверка воркфлоу n8n

Воркфлоу, который работает на тесте, ломается в работе по одним и тем же причинам: ключ в теле узла, вебхук без защиты, сбой, о котором никто не узнал. Скрипт находит это механически; остальное — чтение логики.

## Порядок работы

1. **Получи файл.** Нужен экспорт воркфлоу в JSON (в n8n: меню воркфлоу → Download). Если JSON вставлен в сообщение — сохрани его в файл.

   Сразу предупреди: в экспорте могут быть ключи и данные клиентов. Не пересылать файл дальше, пока проверка не пройдена.
2. **Запусти скрипт** из папки скилла:

   ```bash
   python3 scripts/n8n_lint.py workflow.json
   ```

   Секреты в выводе замаскированы. Не выводи полные значения ключей в ответ, даже если видишь их в файле.
3. **Разбери находки** по важности:
   - `critical` — ключ или токен записан в узле. Действие одно: перенести в Credentials **и перевыпустить ключ** — он уже попал в файл.
   - `high` — вебхук без аутентификации, вероятный секрет.
   - `medium` — нет повторов, ошибка проглатывается, нет воркфлоу для ошибок, закреплённые данные, http без шифрования.
   - `low` и `info` — имена узлов, таймауты, документация.

   Проверь каждую находку `possible_secret` глазами: скрипт судит по имени параметра и может ошибиться.
4. **Прочитай логику сам** — то, чего скрипт не видит. Пройди по [references/review-checklist.md](references/review-checklist.md): что запускает воркфлоу, что будет при повторном запуске с теми же данными, что при пустом или неожиданном входе, куда уходят данные, есть ли действия, которые нельзя отменить.
5. **Если в воркфлоу есть AI-агент** (скрипт сообщит `agent_with_tools`) — проверь по [references/agent-security-checklist.md](references/agent-security-checklist.md), разделы 2 и 3: какие у агента инструменты и читает ли он внешний контент. Агент, который читает письма или сайты и при этом может отправлять данные наружу, — главный риск.
6. **Составь отчёт** по [assets/review-report.md](assets/review-report.md) и сохрани в `n8n-review.md`: вывод одной строкой (можно запускать / можно после исправлений / нельзя), находки по важности с исправлением для каждой, что проверено вручную, что не проверялось.

## Правила

- Никогда не печатай найденный секрет целиком и не предлагай «временно оставить».
- Ключ, попавший в экспорт, считается раскрытым: убрать из узла недостаточно, нужен перевыпуск.
- Не исправляй JSON молча. Покажи, что и где менять в интерфейсе n8n; правленый файл отдавай только по просьбе и с перечнем изменений.
- Скрипт проверяет структуру, а не поведение: он не запускает воркфлоу. Скажи это в отчёте.
- Если находок нет — не пиши «воркфлоу безопасен». Пиши, что автоматическая проверка проблем не нашла, и что проверено вручную.

## Чего скрипт не проверяет

- Права учётных данных в сторонних системах.
- Корректность выражений и логику ветвлений.
- Нагрузку и лимиты API.
- Настройки самого сервера n8n: доступ, шифрование, резервные копии.
