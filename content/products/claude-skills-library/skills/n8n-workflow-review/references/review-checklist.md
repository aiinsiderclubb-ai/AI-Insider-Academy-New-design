# Ручная проверка воркфлоу

То, что скрипт не видит. Пройди по порядку; каждое «нет» — находка.

## 1. Запуск

- [ ] Понятно, что запускает воркфлоу и как часто.
- [ ] Вебхук проверяет, что запрос пришёл от ожидаемой системы: заголовок с секретом или подпись.
- [ ] Для вебхуков от платёжных и других сервисов проверяется подпись, а не только наличие заголовка.
- [ ] Расписание не запускает воркфлоу чаще, чем нужно, и не накладывается само на себя при долгом выполнении.

## 2. Повторный запуск

Сервисы повторяют вебхуки, пользователи нажимают кнопку дважды.

- [ ] Повторный запуск с теми же данными не создаёт дубль: сделку, счёт, письмо, запись в календаре.
- [ ] Есть ключ, по которому дубль определяется: номер заказа, идентификатор события.
- [ ] Действия, которые нельзя отменить, выполняются после проверки на дубль, а не до.

## 3. Входные данные

- [ ] Обработан пустой вход: ни одной строки, пустое поле.
- [ ] Обработан неожиданный вход: другой язык, очень длинный текст, вложение, спецсимволы.
- [ ] Данные из внешнего источника не подставляются напрямую в запрос к базе, в код или в команду.
- [ ] Телефоны, даты, суммы приводятся к одному формату до сравнения и записи.
- [ ] Часовой пояс указан явно там, где есть время.

## 4. Ошибки

- [ ] У каждого обращения к внешней системе есть повторы и ветка на случай отказа.
- [ ] Ошибка не проглатывается: о ней узнаёт человек.
- [ ] Назначен воркфлоу для ошибок с уведомлением в канал, который читают.
- [ ] В уведомлении есть название воркфлоу, узел, текст ошибки и ссылка на запуск.
- [ ] Понятно, что делать с данными, которые не обработались: очередь, повтор, ручная обработка.
- [ ] Частичный сбой не оставляет систему в половинчатом состоянии: сделка создана, а письмо не ушло.

## 5. Данные

- [ ] Известно, какие персональные данные проходят через воркфлоу.
- [ ] Данные уходят только в те системы, о которых знает владелец.
- [ ] В модель отправляется только то, что нужно для задачи.
- [ ] В журнале запусков не остаются лишние данные; срок хранения ограничен.
- [ ] Закреплённые тестовые данные удалены.
- [ ] В заметках и названиях узлов нет ключей и данных клиентов.

## 6. Действия

- [ ] Составлен список того, что воркфлоу меняет во внешнем мире.
- [ ] Действия с деньгами, удалением и правами доступа требуют подтверждения человеком.
- [ ] Сообщения клиентам идут по шаблону или через проверку.
- [ ] Есть лимит: сколько писем, сообщений, записей может создать один запуск.
- [ ] Цикл не может стать бесконечным.

## 7. Учётные данные

- [ ] Все ключи — в Credentials, а не в узлах, выражениях или Code.
- [ ] У каждой учётной записи минимальные права: только чтение там, где запись не нужна.
- [ ] Используется отдельная учётная запись для автоматизации, а не личная.
- [ ] Известно, кто владелец каждого ключа и когда его менять.

## 8. Поддержка

- [ ] Узлы названы по действию.
- [ ] В начале воркфлоу есть заметка: что делает, кто владелец, дата.
- [ ] Сложные места объяснены заметками.
- [ ] Нет отключённых и неподключённых узлов без объяснения.
- [ ] Есть копия предыдущей рабочей версии.
- [ ] Известно, как выключить воркфлоу, и это умеют минимум двое.

## Вывод

| Ситуация | Вывод |
|---|---|
| Есть `critical` или `high`, или «нет» в разделах 2, 4, 6 при необратимых действиях | Запускать нельзя |
| Только `medium` и ниже, «нет» в разделах 3, 5, 8 | Можно после исправлений из списка |
| Замечаний уровня `low` и ниже | Можно запускать |
