# Коммерческое предложение

Предложение, которое клиент может согласовать без дополнительного звонка: его цифры, понятный объём, три варианта цены и явный список того, что не входит.

## Что нужно на входе

- Итоги разговора с клиентом. Если есть `call-debrief.md` — возьми факты и расчёт оттуда.
- Выгода клиента в месяц, согласованная с ним. Нет согласованной цифры — предупреди: без неё цена не защищается, и предложи сначала досчитать.
- Оценка часов на проект и ставка пользователя.
- Что именно строим: процессы, каналы, интеграции.

## Порядок работы

1. **Посчитай цену** скриптом из папки скилла:

   ```bash
   python3 scripts/pricing.py --hours 45 --rate 50 --monthly-benefit 1475 \
     --services-cost 60 --support 400
   ```

   Скрипт даёт себестоимость с запасом, диапазон цены от ценности (10–30% годовой выгоды), три пакета, окупаемость и предупреждения. Прочитай `warnings`: если проект не окупается в заданном объёме — скажи это пользователю прямо и предложи сократить объём, а не «подогнать» цифры. Свою цену можно задать через `--price`.
2. **Определи три пакета по объёму**, а не только по цене: что убираем в «Старте», что добавляем в «Полном». Правила — в [references/pricing-guide.md](references/pricing-guide.md). Основной пакет — тот, который пользователь хочет продать.
3. **Заполни предложение** по [assets/proposal-template.md](assets/proposal-template.md). Раздел «Что мы услышали» — словами клиента. Раздел «Что не входит» заполняй так же тщательно, как «Что входит».
4. **Заполни описание работ** по [assets/scope-of-work.md](assets/scope-of-work.md): каждый результат — с критерием приёмки, который можно проверить («10 тестовых заявок из каждого канала создают карточку в CRM без ручных действий»), а не «система работает».
5. **Проверь** по списку ниже.
6. **Сохрани** `proposal.md` и `scope-of-work.md`. В ответе пользователю: цена основного пакета, окупаемость, предупреждения скрипта и то, что осталось незаполненным.

## Правила

- Все цифры в разделе про выгоду — из расчёта, согласованного с клиентом. Свои оценки помечай как оценки.
- Срок всегда «с момента получения доступов».
- Расходы клиента на сторонние сервисы названы отдельной строкой.
- Скидка только через изменение объёма. «Могу за 1 800 вместо 2 800: без канала WhatsApp и отчёта руководителю».
- Не гарантируй рост продаж. Гарантировать можно срок, работоспособность и бесплатные исправления в период поддержки.
- Поддержку предлагай в этом же документе: после запуска срочность у клиента пропадает.
- Предложение — не договор. Если пользователь просит договор, скажи, что шаблон нужно показать юристу.

## Проверка перед отправкой

- [ ] Объём понятен человеку, который не был на звонке.
- [ ] Есть раздел «Что не входит».
- [ ] Три варианта цены, основной выделен.
- [ ] Указан срок действия предложения.
- [ ] Окупаемость посчитана по цифрам клиента.
- [ ] Каждый результат в описании работ имеет проверяемый критерий.
- [ ] Указано, что нужно от клиента и к какому сроку.
- [ ] Есть следующий шаг с датой.
- [ ] Не осталось `[скобок]` с незаполненными местами.
