# Отчёт клиенту

Отчёт отвечает на три вопроса: что изменилось, почему и что делаем дальше. Проценты считает скрипт — модель в арифметике ошибается, а ошибка в отчёте стоит доверия.

## Что нужно на входе

- Показатели за текущий и прошлый период. Лучше всего — CSV по образцу [assets/metrics-sample.csv](assets/metrics-sample.csv): `metric, previous, current, target, direction, unit`. Если цифры даны в сообщении — собери CSV сам и покажи его пользователю перед расчётом.
- Что сделано за период и что планируется.
- Для кого отчёт: клиент, руководитель, команда.
- Расчёт из предложения, если он был, — чтобы сравнить факт с обещанным.

Для показателей, где меньше — лучше (время ответа, стоимость заявки, число ошибок), в колонке `direction` должно стоять `down`. Проверь это: иначе улучшение будет показано как ухудшение.

## Порядок работы

1. **Посчитай изменения** скриптом из папки скилла:

   ```bash
   python3 scripts/metrics_delta.py metrics.csv
   python3 scripts/metrics_delta.py metrics.csv --format md
   ```

   Первый вызов даёт данные для анализа, второй — готовую таблицу для отчёта. Если есть `unreadable_rows` — покажи их пользователю, не выбрасывай молча.
2. **Найди главное.** Из `biggest_improvements`, `biggest_declines` и `off_target` выбери два-три показателя, которые важны читателю. Не пересказывай всю таблицу словами.
3. **Объясни причины** — только те, что названы пользователем или следуют из его описания работ. Не знаешь причину — напиши «причина не установлена, проверяем» и спроси. Выдуманное объяснение хуже отсутствующего.
4. **Напиши отчёт** по [assets/report-template.md](assets/report-template.md), соблюдая [references/writing-rules.md](references/writing-rules.md). Одна страница.
5. **Проверь цифры:** каждое число в тексте должно совпадать с таблицей скрипта. Проценты не пересчитывай в уме.
6. **Сохрани** `report.md`. В ответе — отчёт и отдельно вопросы к пользователю: чего не хватило.

## Правила

- Плохие новости — в начале и прямо. «Выручка снизилась на 4%» в первом абзаце, а не в конце мелким шрифтом.
- Не подменяй показатель: если цель по конверсии не выполнена, не пиши вместо этого про рост заявок.
- Процент без базы не считается: когда прошлое значение ноль или его нет, пиши абсолютное значение.
- Маленькие числа — в штуках, а не в процентах: «с 2 до 3 заявок», а не «+50%».
- Не приписывай результат своей работе, если причина не установлена.
- Одно предложение в конце, с цифрой и следующим шагом. Не список из пяти идей.
- Не добавляй прогнозов, если пользователь о них не просил.
