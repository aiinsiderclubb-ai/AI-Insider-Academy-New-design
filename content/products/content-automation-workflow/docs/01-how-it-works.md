# Как это работает

## Путь одной публикации

```
idea          — тема в таблице (от бота или ваша)
  ↓ Drafts: за draft_ahead_hours до публикации
draft_ready   — черновик в таблице и в чате одобрения
  ↓ Опубликовать / ваш текст в ответ
approved      — ждёт времени публикации
  ↓ Publisher: время наступило
publishing    — отмечено перед отправкой
  ↓
published     — ссылка в колонке link
```

Ветки: **Переписать** возвращает в `idea` (бот учтёт прошлый вариант и замечание); **Пропустить** — `skipped`; сбой — `failed` и причина в `error`.

## Лист Plan

Заголовки — первая строка (шаблон: `templates/plan-starter.csv`). Колонки A–G заполняете вы, H–Q ведут воркфлоу; их тоже можно править руками.

| Колонка | Что это |
|---|---|
| `id` | Идентификатор. Пусто — бот присвоит сам. До 50 знаков, без пробелов |
| `publish_at` | Когда публиковать: ячейка-дата или текст `2026-10-28 10:00` / `28.10.2026 10:00`, по часовому поясу из Config. Пусто — сразу после одобрения |
| `channel` | Ключ канала из Config: `telegram`, `blog`, `linkedin` или ваш |
| `topic` | Тема |
| `brief` | О чём пост, главный тезис, факты, которые можно использовать |
| `pillar` | Рубрика |
| `image_url` | Ссылка на картинку (https). Telegram отправит фото, WordPress вставит в начало статьи |
| `status` | `idea` → `draft_ready` → `approved` → `publishing` → `published`; также `failed` и `skipped` |
| `title` | Заголовок от модели — для блога |
| `draft` | Черновик модели |
| `final` | Что будет опубликовано: черновик после одобрения или ваш текст |
| `attempts` | Неудачные попытки написать черновик |
| `approved_by` | Кто одобрил |
| `published_at` | Когда вышло |
| `link` | Ссылка на публикацию |
| `error` | Причина сбоя |
| `notes` | Замечание к переписыванию («короче и с примером») |

## Ручное управление

- **Своя тема** — новая строка со статусом `idea`.
- **Свой готовый текст** — заполните `final`, статус `approved`. Бот опубликует в срок без черновика.
- **Поправить одобренный пост** — исправьте `final` до времени публикации.
- **Повторить после сбоя** — исправьте причину, поставьте новую дату и статус `approved` (или `idea`, чтобы бот написал заново).
- **Остановить** — статус `skipped`.

## Почему по одной публикации за запуск

Publisher запускается каждые 5 минут и публикует одну запись — самую раннюю из наступивших. Так результат каждой публикации записывается до следующей, и ничего не выходит дважды. Если в один слот назначено несколько каналов, они выйдут с интервалом 5 минут.

## Часовой пояс

Все даты — по `timezone` из Config, с учётом перехода на летнее время. Дата, которую бот не понял, — статус `failed` и причина.
