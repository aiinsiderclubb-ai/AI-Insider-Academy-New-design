# Как проверены воркфлоу

## Логика узлов Code — 9 сценариев

1. Даты: ячейка-дата, `2026-10-28 10:00` и `28.10.2026 10:00` — одно время по Киеву; летнее время; непонятная дата отклоняется.
2. План недели: слоты по дням и времени, заголовки при первой записи, формула из темы обезврежена, повторный план — пусто.
3. Модель не придумала темы — сообщение в чат, таблица не тронута.
4. Черновик: самая ранняя идея в пределах 48 часов, id присваивается, неизвестный канал и непонятная дата — `failed` с причиной.
5. Слишком длинный текст — повтор, третья неудача — `failed` и сообщение.
6. Кнопки и ответы: одобрить, переписать с замечанием (модель получает прежний вариант и замечание), заменить текст, пропустить; чужой чат игнорируется.
7. Публикация: по времени, сначала отметка `publishing`, ссылка Telegram и вебхука.
8. Длинный текст с фото — фото, затем текст; Markdown для WordPress — HTML.
9. Отказ сервиса — `failed` и текст ошибки; пост, опоздавший больше чем на 12 часов, не публикуется.

## Запуск в n8n 2.44

Воркфлоу импортированы в n8n; расписания запускались вручную, Telegram — через вебхук с тем же содержимым. Google Таблицы, модель, Telegram, WordPress и вебхук заменены локальным сервером с теми же форматами запросов и ответов.

- Weekly Plan → пять строк `idea` и план в чате; второй запуск ничего не добавляет.
- Drafts → черновик с id в таблице и в чате с кнопками; неизвестный канал — `failed` и сообщение; третья неудача модели — `failed` и сообщение.
- Кнопка «Опубликовать» → `approved`, имя в таблице; ответ своим текстом → текст заменён.
- Publisher → запись в WordPress с HTML и ссылкой; пост в Telegram-канал с одобренным текстом и ссылкой `t.me`.
- Вебхук ответил 500 → `failed`, текст ошибки, сообщение в чат; следующий запуск ничего не публикует повторно.

## Что не проверялось

- Настоящие Telegram, WordPress, Make и Google Таблицы под вашими учётными данными — проверьте по `test-requests.md`.
- Качество текстов конкретной модели в вашем голосе — две недели с одобрением.
