# Как это работает

## Путь сделки

```
Заявка (любой источник, с токеном)
  → очистка полей, телефон в +380…, почта строчными
  → поиск клиента по телефону и почте
       открытая сделка есть  → запись в историю, карточка ответственному
       была закрытая сделка  → новая сделка тому же менеджеру, «повторный»
       новый клиент          → новая сделка, менеджер по очереди
  → первый шаг: «Позвонить клиенту» через 30 минут (или в начале рабочего дня)
  → карточка с кнопками менеджеру, короткое сообщение в чат команды

Менеджер: кнопки этапов → у каждого этапа свой следующий шаг и срок
Бот: напоминает о шаге, сообщает о брошенной заявке, будит застрявшие сделки
Понедельник: отчёт
```

## Лист Deals

| Колонка | Что это |
|---|---|
| `id` | Номер сделки: `D261026-3` — дата и порядковый номер за день |
| created_at / updated_at | Создана / изменена — местное время `2026-10-26 10:00` |
| `source` | Источник: `tilda`, `site`, `whatsapp`… Передаётся полем `source` |
| name, phone, email, company | Контакт. Телефон — `+380…`, почта — строчными |
| `need` | Запрос клиента |
| `amount` | Сумма сделки. Из поля `amount`/`budget` или ответом «сумма: 1500» |
| `stage` | Этап: `id` из `stages` |
| `owner` | Ответственный — имя из `owners` |
| next_action / next_action_at | Следующий шаг и когда. Можно править руками: `2026-10-28 15:00` |
| `last_activity_at` | Последнее действие по сделке |
| reminded_at / escalated_at | Когда напоминали / сообщали команде — защита от повторов |
| `lost_reason` | Причина проигрыша |
| `closed_at` | Когда выиграна или проиграна |
| `repeat` | `yes` — повторный клиент |
| `history` | Все события сделки с датой и автором |
| `notes` | Свободная колонка |

Таблицу можно править руками: поменять ответственного, этап, дату следующего шага. Не переставляйте колонки A–V; свои колонки добавляйте правее.

## Распределение

1. Повторный клиент — тому же менеджеру, если он активен.
2. Иначе — активному менеджеру с наименьшим числом открытых сделок.
3. При равенстве — тому, кто дольше не получал новую сделку.

Менеджер в отпуске — `"active": false` в `owners`. Его сделки остаются за ним; передайте их, поменяв `owner` в таблице.

## Этапы

```json
{ "id": "proposal", "label": "КП отправлено", "next_action": "Узнать решение", "follow_up_days": 3, "stale_days": 4 }
```

- `next_action` и `follow_up_days` — какой шаг ставится при переходе на этап и через сколько дней.
- `stale_days` — через сколько дней без движения бот напомнит о сделке.
- `won` и `lost` — обязательные этапы закрытия; их `id` не меняйте.
- Кнопки на карточке — для `contacted`, `meeting`, `proposal`, `won`, `lost`. Свои этапы с другими `id` выставляйте в таблице; подписи меняйте свободно.

## Напоминания

Каждые 15 минут в рабочее время:

| Что | Кому | Сколько раз |
|---|---|---|
| Наступил `next_action_at` | Ответственному, карточка с кнопками | Один раз на каждый новый срок |
| Новая сделка дольше `escalate_after_minutes` | Чат команды | Один раз |
| Нет движения дольше `stale_days` и нет будущего шага | Ответственному | Не чаще раза в сутки |
