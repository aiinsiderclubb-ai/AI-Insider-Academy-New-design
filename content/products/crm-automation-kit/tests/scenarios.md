# Как проверены воркфлоу

## Логика узлов Code — 9 сценариев

1. Неверный токен — 403; тестовый запрос Tilda (по токену в адресе) — ok без записи; заявка без телефона и почты — 422.
2. Новая заявка: поля Tilda распознаны, телефон `067…` → `+38067…`, почта строчными, ответственный, первый шаг через 30 минут, карточка и сообщение команде.
3. Распределение по нагрузке; неактивный менеджер не получает заявок; вечерняя заявка получает шаг на утро понедельника.
4. Повторное обращение при открытой сделке — та же сделка; после выигранной — новая сделка тому же менеджеру с контактами из прошлой.
5. Кнопки этапов: следующий шаг и срок по этапу, повторное нажатие ничего не меняет, выигрыш и проигрыш — сообщение команде.
6. Ответы: сумма, «напомнить» в четырёх формах и непонятная дата, заметка, причина проигрыша; чужой чат игнорируется; /start отвечает chat id.
7. «Завтра» и /my.
8. Напоминания: ночью тишина; эскалация и напоминание один раз; застрявшие сделки — не чаще раза в сутки.
9. Отчёт: новые, повторные, выигрыш с суммой, конверсия, причины, менеджеры; неактивный без сделок не показывается.

## Запуск в n8n 2.44

Воркфлоу импортированы в n8n и вызваны по HTTP; расписания запускались вручную, Telegram — через вебхук с тем же содержимым. Google Таблицы и Telegram заменены локальным сервером с теми же форматами запросов и ответов.

- Неверный токен → 403; тестовый запрос Tilda → ok, таблица пуста; без контактов → 422.
- Форма Tilda (url-encoded) → сделка Олегу, телефон в международном формате, карточка с кнопками в личку, сообщение команде.
- Следующая заявка → Ане; тот же телефон → та же сделка, без дубля.
- Кнопка «Связались» → этап и шаг; ответ «напомнить: завтра 11:00 отправить КП» → шаг и время; «Выиграна» → сообщение команде.
- /my → список сделок менеджера; сообщение из чужого чата → ничего.
- Reminders → эскалация в чат команды и напоминание; повторный запуск — тишина.
- Weekly Report → отчёт с выигранной суммой.
- Таблица недоступна → источнику 503, команде — заявка целиком.
