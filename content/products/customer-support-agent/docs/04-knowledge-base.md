# База знаний и заказы

## Как пишутся статьи

Лист `Knowledge`, одна строка — одна статья:

| Колонка | Что писать |
|---|---|
| `id` | короткий код: `KB-01`. Агент может сослаться на него, вы — найти статью по журналу |
| `question` | вопрос так, как его задаёт клиент: «Сколько идёт доставка?» |
| `answer` | полный ответ: цифры, сроки, условия. Агент перескажет его своими словами, но фактов не добавит |
| `tags` | слова, которыми спрашивают о том же: `доставка сроки отправка нова пошта` |
| `updated` | дата проверки статьи — для вас |

Хорошая статья:
- отвечает на один вопрос;
- содержит все цифры и условия — агент не возьмёт их из головы;
- в `tags` — синонимы и разговорные слова: «вернуть», «возврат», «обмен», «не подошло».

Плохая статья: «Условия доставки и оплаты» на две страницы. Разбейте её на 4–6 коротких — поиск находит их точнее.

Агент берёт до трёх лучших статей на запрос. Если вопрос шире — он вызовет поиск ещё раз с другими словами.

## Как работает поиск

Поиск без векторной базы — по словам с учётом окончаний (русский и английский): «доставки», «доставку» и «доставка» — одно слово. Совпадение в `question` или `tags` весит больше, чем в `answer`. Редкие слова весят больше частых.

Оценка статьи — доля слов вопроса, которые в ней нашлись, от 0 до 1. Если у лучшей статьи оценка ниже `kb_min_score` (0.3), агент получает «в базе нет ответа» и не отвечает по памяти.

- Агент часто говорит «не нашёл», хотя статья есть → добавьте в `tags` слова клиента или снизьте `kb_min_score` до 0.2.
- Агент отвечает не той статьёй → повысьте порог до 0.4 или разделите статью.

Такой поиск уверенно работает до нескольких сотен статей. Если база — это сотни страниц документов, PDF и регламентов, нужен векторный поиск: смотрите наш Knowledge Base Agent или замените ветку Read Knowledge → Rank Articles на узлы Vector Store n8n.

После правки базы прогоните evals (`docs/07-evals.md`): правка статьи может поменять ответы на соседние вопросы.

## Заказы из магазина вместо таблицы

Лист `Orders` подходит для старта и небольших магазинов. Чтобы агент брал данные прямо из магазина, замените узел **Read Orders** на HTTP Request к API магазина и поправьте **Find Order**. Важно, чтобы Find Order по-прежнему:

1. находил заказ по номеру;
2. сверял email или телефон клиента с заказом;
3. возвращал данные заказа, только если проверка пройдена.

Примеры запросов:
- **Shopify:** `GET https://МАГАЗИН.myshopify.com/admin/api/2025-10/orders.json?name=%231001&status=any` с заголовком `X-Shopify-Access-Token`.
- **WooCommerce:** `GET https://САЙТ/wp-json/wc/v3/orders/1001` с ключом REST API.

Версию API и права ключа проверьте в документации своей платформы.

## Без заказов

Если статус заказа агенту не нужен:
1. удалите узел **get_order_status** (под агентом);
2. удалите из `agent/system-prompt.md` и из системной инструкции в узле AI Agent пункт 3 раздела «Как ты работаешь» и строку «Не сообщаешь данные заказа…»;
3. удалите ветку Read Orders → Find Order — или оставьте, она не мешает.
