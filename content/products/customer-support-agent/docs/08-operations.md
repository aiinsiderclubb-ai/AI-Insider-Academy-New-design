# Эксплуатация

## Журнал

Лист `Log` — каждый ответ агента: время, сессия, канал, вопрос, ответ, вызванные инструменты, передача, пометки, номер обращения.

Раз в неделю отфильтруйте:
- `flags` содержит `forbidden_promise` — где агента тянуло обещать лишнее. Уточните базу или инструкцию;
- `flags` содержит `injection` — кто и как пытался сломать агента;
- `tools` пусто, а вопрос по существу — агент ответил без поиска;
- `handoff = да` — какие темы чаще всего уходят людям. Частые простые темы — кандидаты в новые статьи;
- `service_error` — сбои таблицы или Telegram.

## Память диалога

Узел Memory (Simple Memory) хранит переписку в памяти процесса n8n:
- после перезапуска n8n агент забывает начатые диалоги;
- в режиме очереди (queue mode) с несколькими воркерами разные сообщения одного диалога могут попасть на разные воркеры и не увидеть друг друга.

Для production с очередью замените Memory на **Postgres Chat Memory** или **Redis Chat Memory**: тот же `Session Key` — `{{ $('Guard In').first().json.session_id }}`, та же длина окна.

## Приватность

- Журнал хранит текст сообщений. Номера карт вырезаются до записи, остальное — как написал клиент. Определите срок хранения и чистите `Log` по нему.
- В модель уходят текст сообщения, имя и контакт клиента, найденные статьи, данные проверенного заказа. Проверьте, что условия вашего провайдера модели подходят для таких данных, и укажите обработку в политике конфиденциальности.
- Запросы на удаление данных (KB-19 в демо-базе) выполняются вручную: строки в `Log`, `Tickets`, `Orders`.

## Изменения

- **Инструкция.** Правьте `agent/system-prompt.md`, затем перенесите текст в узел AI Agent → Options → System Message. Значения в двойных фигурных скобках, которые ссылаются на Config, не трогайте. После правки — evals.
- **База знаний** правится в таблице и подхватывается сразу.
- **Новый инструмент:** узел Call n8n Workflow Tool у агента (скопируйте существующий), новое значение в Tool Switch, ветка, которая возвращает JSON с полем `note`, строка в системной инструкции — когда его вызывать. Добавьте имя в поля узла Tool Call, если инструменту нужны новые входы.

## Неполадки

| Симптом | Причина |
|---|---|
| вебхук отвечает 401 на всё | в Config осталась заглушка `agent_token`, или токен в запросе не совпадает |
| 404 на Production URL | воркфлоу не опубликован |
| бот в Telegram молчит | не опубликован; бот подключён к другому воркфлоу; n8n не по https |
| агент всегда говорит «в базе нет ответа» | неверный `spreadsheet_id`, лист называется не `Knowledge`, у Google-ключа нет доступа к таблице — в журнале будет `service_error` |
| ответы приходят, но лимиты не работают | тестовый запуск из редактора — статические данные сохраняются только в опубликованном |
| в чат команды ничего не приходит | неверный `team_chat_id`, бота нет в группе, или группа стала супергруппой и сменила ID |
| агент не помнит, что клиент писал минуту назад | `session_id` меняется между сообщениями; n8n перезапускался; queue mode — см. «Память диалога» |
| ошибка провайдера о том, что модель не поддерживает tools | выбранная модель без function calling — смените модель |
