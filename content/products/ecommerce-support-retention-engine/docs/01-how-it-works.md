# Как это работает

Один воркфлоу, семь входов, одна настройка — узел **Config**. Узел **Kind** смотрит, откуда пришёл запрос, и отправляет его в нужную часть.

```
Chat Webhook ─┐
Telegram ─────┤                         ┌─ chat ─────────► Guard In → AI Agent → Guard Out → Log → ответ
Tool Call ────┤                         ├─ tool ─────────► Tool Switch → магазин → Normalize Order → ответ модели
Every 30 min ─┼─► Config ─► Kind ───────┼─ carts ────────► корзины → план → (модель) → письмо → Messages
Every day ────┤                         ├─ reviews ──────► заказы → план → письмо → Messages
Cart Event ───┤                         ├─ cart_event ───► лист Carts
Unsubscribe ──┘                         └─ unsubscribe ──► проверка подписи → Suppress → страница
```

## Ассистент

Устроен как наш Customer Support Agent: Guard In (токен, лимиты, номер карты, «позовите человека») → AI Agent с памятью → Guard Out (запрещённые обещания, утечка инструкции, пустой ответ) → журнал → ответ в тот же канал.

Инструменты — ветки этого же воркфлоу: узел инструмента вызывает воркфлоу с `$workflow.id`, вызов приходит в **Tool Call**.

| Инструмент | Что делает |
|---|---|
| `search_policies` | до трёх правил магазина из листа Policies |
| `get_order` | заказ из платформы → Normalize Order → данные, только если email или телефон совпал |
| `check_return` | заказ → **Return Policy** решает по правилам: eligible / ineligible / needs_human |
| `create_return_request` | то же решение заново, и если возврат возможен — строка в Returns и сообщение команде |
| `handoff_to_human` | пересказ в чат команды |

Решение по возврату принимает код в узле Return Policy, а не модель. Модель видит итог и причины. `create_return_request` проверяет правила ещё раз сам: даже если модель «уговорили», заявка на неподходящий возврат не создастся.

## Заказы из трёх источников

Ветка **Order Source** выбирает платформу по `platform`:
- Shopify — один GraphQL-запрос: заказ, покупатель, товары с типами и тегами, доставки с датой вручения и трек-номером;
- WooCommerce — `GET /wp-json/wc/v3/orders/<номер>`;
- таблица — лист Orders.

**Normalize Order** приводит ответ к одному виду: номер, email, телефон, статус по-русски, отменён или возвращён ли, дата доставки, сумма, товары с типами и тегами, трек-номера. Дальше ассистент, возвраты и отзывы работают одинаково для любой платформы.

## Рассылки

**Корзины** (каждые 30 минут): Shopify отдаёт брошенные оформления за `max_age_hours`, остальные платформы — из листа Carts. **Plan Carts** отбирает, кому писать и какое письмо, по журналу Messages и списку Suppress. Если включено `ai_personalize`, модель пишет первую фразу письма, **Compose Cart Email** её проверяет и собирает письмо. Отправка — SMTP, итог — строкой в Messages.

**Отзывы** (каждый день в 11:00): доставленные заказы → **Plan Reviews** → письмо → Messages.

Обе рассылки останавливаются в тихие часы и не пишут тем, кто в Suppress.

## Что где хранится

- Память диалога — в n8n (узел Memory, 14 последних сообщений).
- Лимиты и паузы ассистента — в статических данных воркфлоу.
- Всё остальное — в вашей таблице: заявки, корзины, письма, отписки, журнал. Движок можно перезапустить или перенести — он ничего не забудет, кроме памяти диалогов.
