# Каналы и события

## Чат на сайте

`templates/chat-widget.html` — кнопка в углу и окно чата. Вставьте перед `</body>`, впишите адрес вебхука `store-agent` и `agent_token`. Токен виден в коде страницы — он отсекает случайные запросы, бюджет защищают лимиты. Подробности про токен и CORS — как в Customer Support Agent: `Allowed Origins` в узле Chat Webhook.

## Telegram

Telegram Trigger подключается при публикации. Нужен отдельный бот для покупателей: тот же бот, что пишет команде, использовать можно, но тогда его сообщения в чате команды тоже придут ассистенту — он их проигнорирует, но лучше разделить.

## API ассистента

```
POST https://ВАШ-N8N/webhook/store-agent
x-agent-token: ВАШ_AGENT_TOKEN

{"session_id": "crm-48213", "message": "Где заказ 1001?", "email": "anna@example.com", "name": "Анна"}
```

Ответ: `{"reply": "...", "handoff": false, "session_id": "crm-48213", "rma": "R-..."}`. `rma` — только если в этом ответе создана заявка на возврат. `email`, переданный системой, ассистент использует для проверки заказа, если покупатель его не назвал.

## События корзины

Для WooCommerce, Tilda, своих сайтов — всех, у кого нет API брошенных корзин. Сайт сообщает два события.

**Покупатель указал email на оформлении:**

```
POST https://ВАШ-N8N/webhook/store-cart-event
x-agent-token: ВАШ_AGENT_TOKEN          (или поле "token" в теле)

{
  "event": "cart",
  "cart_id": "c-81723",                       ваш ID корзины или сессии
  "email": "anna@example.com",                обязателен
  "name": "Анна",
  "consent": true,                            галочка согласия на рассылку
  "items": [{"title": "Плед", "qty": 1}],     или строка «Плед ×1; Подушка ×2»
  "total": 2400,
  "currency": "UAH",
  "checkout_url": "https://shop.example/cart/restore/c-81723"   только https
}
```

Шлите событие при каждом изменении корзины: движок берёт последнее.

**Заказ оформлен** — чтобы письмо не ушло тому, кто уже купил:

```json
{"event": "order", "cart_id": "c-81723", "email": "anna@example.com"}
```

Если `cart_id` в заказе неизвестен, достаточно email: корзина считается купленной, если после неё с этого адреса пришёл заказ.

Ответ: `200 {"ok": true}`, `401` — неверный токен, `400` — не хватает полей.

`checkout_url` должна восстанавливать корзину по ссылке — без неё письмо бесполезно, и движок такую корзину пропускает. В WooCommerce это делают плагины восстановления корзины; на своём сайте — ссылка с ID корзины.

Пример отправки с сайта:

```js
fetch('https://ВАШ-N8N/webhook/store-cart-event', {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ token: 'ВАШ_AGENT_TOKEN', event: 'cart', cart_id, email, consent, items, total, currency, checkout_url }),
});
```

Отправляйте с сервера, если можете: с сервера токен не виден посетителям.

## Ссылка «отписаться»

В каждом письме — ссылка `…/webhook/store-unsubscribe?e=<email>&s=<подпись>`. Подпись — HMAC-SHA256 адреса с `unsubscribe_secret`: подделать ссылку для чужого адреса нельзя. По ссылке адрес попадает в лист Suppress, покупатель видит страницу «Вы отписаны». Отписка касается писем о корзинах и отзывов. Письма о заказах шлёт ваш магазин, а не движок.

Отписать вручную — добавьте строку с email в Suppress.
