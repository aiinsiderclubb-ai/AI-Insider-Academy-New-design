# Возвраты

Главное правило: **ассистент не возвращает деньги и не обещает их вернуть.** Он проверяет возврат по вашим правилам, объясняет итог и создаёт заявку. Деньги возвращает человек в админке магазина после проверки товара.

## Кто решает

Решение принимает код в узле **Return Policy** по `returns` из Config. Модель видит итог и причины и пересказывает их покупателю. Уговорить код нельзя: `create_return_request` проверяет правила заново и для неподходящего возврата заявку не создаёт.

## Порядок проверок

1. Заказ найден, email или телефон покупателя совпадает с заказом. Иначе — ничего не сообщаем.
2. Заказ отменён → **не подходит**. Деньги уже возвращены → **не подходит**, вопросы — менеджеру.
3. Заказ не доставлен → **нужен менеджер**; ассистент подскажет отказаться от посылки при получении.
4. Брак, повреждение, «не тот товар», недовложение (по словам покупателя или `condition: damaged`) → **нужен менеджер** — всегда, даже после срока. Ассистент просит фото.
5. Прошло больше `window_days` с доставки → **не подходит**.
6. Тег финальной распродажи на заказе или все выбранные товары невозвратные (тип из `non_returnable_types` или тег распродажи) → **не подходит**.
7. Товар использовался, а `require_unused: true` → **не подходит**.
8. Сумма заказа больше `human_review_over` → **нужен менеджер**.
9. Иначе → **подходит**, с датой, до которой можно вернуть.

Если покупатель хочет вернуть часть заказа, ассистент передаёт названия — код находит товары по словам. Невозвратные товары из списка исключаются, остальные идут в заявку.

Если неизвестно, был ли товар в использовании, заявка не создаётся: ассистент сначала спросит.

## Заявка

Строка в листе **Returns**:

| Колонка | Что там |
|---|---|
| `rma` | номер заявки, его ассистент называет покупателю |
| `status` | `pending_review` (подходит по правилам) или `needs_human` |
| `decision`, `reasons` | итог и причины проверки |
| `items`, `reason`, `condition` | что возвращают, почему, в каком состоянии |

И сообщение в чат команды с причинами и строкой «деньги автоматически не возвращаются».

Дальше — ваш процесс: инструкция покупателю, приём товара, возврат денег в админке. Статус в Returns меняйте сами (`approved`, `received`, `refunded`, `declined`) — движок его не читает, кроме одного: по заказу с любой заявкой не придёт просьба об отзыве.

## Почему не автоматический возврат

Автоматический возврат денег по решению модели — способ потерять деньги на первом же уговоренном боте. Даже по «подходящей» заявке нужно убедиться, что товар пришёл и цел. Поэтому возврат денег в наборе нет вообще — ни узла, ни права в ключе (ключ Shopify нужен только на чтение).
