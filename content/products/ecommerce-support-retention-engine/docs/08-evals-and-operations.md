# Проверка и эксплуатация

## Evals ассистента

`evals/dataset.jsonl` — 30 случаев на демо-данных: правила магазина (6), заказы (4), возвраты (9), передача человеку (4), действия, которые ассистент делать не должен (1), атаки и посторонние просьбы (5), английский (1).

Как запустить — QUICKSTART, шаг 6. Демо-заказы 5001, 5003 и 5005 должны быть доставлены вчера: срок возврата считается от даты доставки, поэтому дату ставите вы перед прогоном.

```bash
python3 evals/run_evals.py --url 'https://ВАШ-N8N/webhook/store-agent' \
  --token ВАШ_AGENT_TOKEN --debug-token ВАШ_DEBUG_TOKEN --repeat 3
```

Формат случаев и ключи скрипта — как в Customer Support Agent: `tools_include`, `tools_exclude`, `handoff`, `reply_any`, `reply_none`, `language`. Под свой магазин замените вопросы о правилах и заказах на свои, случаи атак и передачи оставьте.

## Как мы проверяли набор

Движок запускался в n8n 2.48 против подменных Shopify GraphQL, WooCommerce REST, Google Таблиц, Telegram, SMTP и моделей с вызовом инструментов, в трёх вариантах: Shopify + OpenAI, WooCommerce + Claude, Google Таблица + OpenAI. 29 проверок:
- ассистент: заказ владельцу и чужому, несуществующий заказ (в том числе 404 WooCommerce), возврат в срок, после срока, финальная распродажа, брак, заявка создаётся и приходит команде, заявка на неподходящий возврат не создаётся, обещание денег блокируется, ответ по правилам;
- корзины: письма только с согласием, некупленным, свежим и не отписанным; фраза модели проходит проверку или заменяется; второй шаг с промокодом; журнал; повторный запуск ничего не дублирует; события корзины с сайта, токен и обязательные поля;
- отписка: подписанная ссылка работает, поддельная — нет;
- отзывы: только по доставленным 7+ дней назад без возврата, один раз; WooCommerce;
- ни одного упавшего выполнения.

Логика узлов Code — ещё 19 тестов. Запросы к Shopify сверены с документацией Admin GraphQL 2026-10, но на настоящем магазине не запускались — проверьте их по QUICKSTART.

## Журналы

- **Log** — каждый ответ ассистента: пометки `forbidden_promise`, `injection`, `service_error`, `card_removed`.
- **Returns** — заявки.
- **Messages** — каждое письмо; `failed` в `status` — SMTP не принял письмо, причина в `detail`.
- **Suppress** — отписки.

## Неполадки

| Симптом | Причина |
|---|---|
| ассистент: «магазин сейчас не отвечает» | неверный токен, адрес или версия API; текст ошибки — в сигнале команде |
| Shopify: заказ не находится | номер заказа в Shopify с префиксом (`#1001`) — ассистент ищет по `name:#номер`. Если у вас префикс другой (`SH-1001`), поправьте выражение в узле Shopify Order |
| старые заказы Shopify не находятся | без `read_all_orders` Shopify отдаёт только последние 60 дней |
| письма о корзинах не уходят | тихие часы; нет согласия; нет ссылки восстановления; `carts.enabled: false`; Shopify не отдаёт корзины без права на брошенные оформления |
| в Messages `failed` | SMTP: логин, порт, отправитель не совпадает с ящиком |
| письмо пришло дважды | включены встроенные письма Shopify о корзине |
| отписка «недействительна» | сменили `unsubscribe_secret` после отправки письма |
| просьбы об отзыве не приходят (WooCommerce) | заказы не в статусе «Выполнен» или нет `date_completed` |
| лимиты ассистента не работают | тестовый запуск: статические данные сохраняет только опубликованный воркфлоу |

## Память и масштаб

Память диалога — в n8n (Simple Memory): после перезапуска диалоги начинаются заново, в queue mode замените на Postgres или Redis Chat Memory с тем же Session Key. Рассылки обрабатывают до `per_run_limit` писем за запуск. Для тысяч корзин в день поднимите лимит и проверьте лимиты своего SMTP.
