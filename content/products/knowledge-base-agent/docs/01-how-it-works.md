# Как это работает

В одном воркфлоу живут три процесса: ответ на вопрос, инструменты агента и переиндексация.

## Вопрос

```
Webhook / Telegram ─► Config ─► Guard In ─► AI Agent ◄── Memory
                                   │          │  ▲
                                   │          │  └── search_documents · list_documents · handoff_to_human
                                   │          ▼
                                   │      Guard Out ── ссылки → список источников
                                   ▼          │
                               заготовка ─────┴─► Log ─► Gaps (если ответа нет) ─► ответ
```

1. **Guard In** проверяет доступ: в Telegram — ID пользователя по списку `allowed_telegram_ids`, в вебе — токен. Дальше — лимиты, номер карты, просьба позвать человека.
2. **AI Agent** ищет по документам инструментом `search_documents`: вопрос превращается в эмбеддинг, индекс возвращает самые близкие по смыслу фрагменты.
3. **Rank Passages** оставляет только фрагменты с оценкой не ниже `min_score` — до `max_passages` штук. Каждый фрагмент несёт код документа: `[d3]`. Если близких нет — агент получает `found: false` и указание не отвечать по памяти.
4. Агент пишет ответ и ставит после утверждений коды документов.
5. **Guard Out** меняет коды на номера `[1]`, `[2]` и добавляет список источников с адресами. Код документа, которого поиск не возвращал, удаляется из ответа (пометка `bad_citation`). Если ни один поиск ничего не нашёл — пометка `not_found`, и вопрос записывается в лист `Gaps`.

## Переиндексация

```
Every Night / Reindex Webhook ─► Reindex Gate ─► List Drive Files ─► Read Sources ─► Plan Sources
      ─► Extract Documents (по одному документу) ─► Build Docs ─► Insert Index ─► Registry ─► Write Registry ─► отчёт в Telegram
```

1. **Plan Sources** берёт файлы папки Drive и включённые строки листа `Sources`. Поддерживаемые форматы — `docs/04-search.md`; остальные попадают в отчёт как пропущенные.
2. **Extract Documents** вызывает этот же воркфлоу для каждого документа: ветка `extract_document` скачивает файл или страницу и превращает его в текст. Ошибка одного документа не останавливает остальные.
3. **Build Docs** присваивает документам коды `d1, d2…` и решает, можно ли менять индекс. Если папка не прочиталась или не прочитан ни один документ — переиндексация останавливается, старый индекс остаётся.
4. **Insert Index** режет тексты на фрагменты (`chunk_size`, `chunk_overlap`), считает эмбеддинги и **заменяет** индекс целиком (Clear Store). Так удалённые из папки документы исчезают из ответов.
5. **Registry** пишет лист `Documents`: код, название, адрес, число фрагментов, статус. Итог — в чат команды.

Индекс заменяется целиком, поэтому коды `d1…` после переиндексации могут поменяться. Ответы, отправленные раньше, ссылаются на документы по названию и адресу в списке источников — они остаются верными.

## Хранилище индекса

По умолчанию — Simple Vector Store: индекс в памяти процесса n8n, без отдельной базы. Это удобно для старта, но индекс пропадает при перезапуске n8n, а в режиме очереди с несколькими воркерами у каждого воркера свой. Для работы без этих ограничений — `docs/05-production-store.md`.
