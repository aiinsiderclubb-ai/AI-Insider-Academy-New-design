# Как это работает

```
Форма на сайте ──► Lead Intake
                    │
                    ├─ проверка токена ── неверный → 403
                    ├─ нет телефона и почты → 422 «Укажите телефон или email»
                    ├─ ответ форме: 200 «Спасибо!»  (сразу, дальше форма не ждёт)
                    │
                    ├─ чтение таблицы → тот же человек за 30 дней?
                    │      ├─ двойной клик (тот же текст за 2 минуты) → стоп
                    │      ├─ да → повторное обращение: обновить его строку
                    │      └─ нет → новая строка
                    ├─ спам? → строка со статусом spam, никому не сообщать
                    ├─ модель включена → оценка 1–5, намерение, кратко, что уточнить
                    │      └─ модель не ответила или ответила не JSON → оценка по правилам
                    ├─ запись в таблицу ── не получилось → вся заявка в Telegram
                    ├─ Telegram: оценка ≥ порога → горячий чат, иначе общий
                    └─ письмо клиенту (если включено)

SLA Reminder (каждые 10 минут, в рабочее время)
    заявки со статусом new дольше 15 минут → напоминание в чат
    дольше 60 минут → руководителю
    каждое напоминание — один раз

Daily Report (9:00)
    вчерашние заявки: сколько, источники, кампании, горячие, спам, кто ждёт
```

## Решения, которые стоит знать

**Ответ форме до всей обработки.** Посетитель получает «Спасибо» за доли секунды. Если дальше что-то сломается, заявка не потеряется: при сбое таблицы она целиком уходит в Telegram, при сбое модели оценку ставят правила.

**Спаму отвечают «спасибо».** Если бот получит ошибку, он поменяет тактику. Спам пишется в таблицу со статусом `spam` — чтобы вы видели, что фильтр работает, и могли вернуть ошибочно отсеянную заявку. Выключить хранение спама: `store_spam: false`.

**Повтор — не новая заявка.** Человек, который написал второй раз за 30 дней, — тот же клиент. Его строка обновляется: растёт счётчик обращений, в заметки дописывается новое сообщение, статус `won` или `lost` возвращается в `new`. Менеджер видит историю в одной строке.

**Таблица — единственное хранилище.** Не нужна база данных и отдельная CRM. Если CRM появится, добавьте после «Write Sheet» узел своей CRM — данные заявки уже приведены к одному виду.

## Узлы Code

| Узел | Что делает |
|---|---|
| Config | Настройки. Единственный узел, который нужно править |
| Parse Lead | Токен, тестовый запрос, разбор полей любой формы, телефоны и почта, признаки спама |
| Dedupe | Поиск того же человека, номер строки, запрос к модели |
| Score Lead | Ответ модели или правила, запись в таблицу, текст сообщения, автоответ |
| Sheet Failed | Сохранение заявки в Telegram, если таблица недоступна |

Логику менять не нужно. Если меняете — повторите запросы из `tests/test-requests.md`.
