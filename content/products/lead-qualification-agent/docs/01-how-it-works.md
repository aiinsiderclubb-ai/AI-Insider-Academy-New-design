# Как это работает

```
форма ─► Lead Webhook ─► Config ─► Intake ── токен, поля, телефон, домен, ловушка для ботов, двойной клик
                                     │
                    ┌────────────────┼──────────┬──────────┐
                    ▼                ▼          ▼          ▼
                 Debug? ─► 202     401        400     200 (бот, повтор)
                    │
                 Read CRM ─► Dedupe ── та же почта, телефон или домен за 90 дней
                    │
                 AI Agent ── fetch_page (только сайт лида) · submit_assessment (значения из списков)
                    │
                 Score ── баллы по рубрике: факты из формы — кодом, суждения — из оценки модели
                    │
                 Route ── сегмент, менеджер по кругу, строка CRM, карточка, письмо лиду
                    │
                 Write CRM ─► After Write ─► Notify (менеджер, отдел) ─► Clarify Email (если включено)
```

1. **Intake** принимает заявку с любой формы: поля `Name`, `Имя`, `E-mail`, `Телефон`, `Comments`… распознаются сами. Телефон приводится к виду `+380501112233`, email — к нижнему регистру. Домен компании берётся из сайта, а если сайта нет — из корпоративной почты (не из gmail). Скрытое поле-ловушка отсекает ботов, повтор той же заявки за 10 минут — двойной клик.
2. **Ответ форме — сразу.** Посетитель получает `202 {ok, lead_id}` до того, как модель начнёт думать: форма не ждёт.
3. **Dedupe** ищет лида в листе `Leads` за `dedupe_days`: по почте, телефону или домену компании. Повтор попадает в ту же строку и к тому же менеджеру.
4. **AI Agent** читает заявку и при наличии сайта открывает до `max_pages` страниц — главную, «о компании», «услуги». Затем сдаёт оценку через `submit_assessment`: подходит ли под идеального клиента, ясен ли запрос, размер компании, сроки, суть для менеджера, вопросы на звонок, красные флаги. Значения — только из списков; иначе инструмент возвращает ошибки, и модель исправляет.
5. **Score** считает баллы по рубрике из Config. Бюджет, корпоративная почта, телефон — код по форме. Подходит ли, ясен ли запрос, размер, сроки — по оценке модели. Каждый критерий даёт строку-причину: «+15 Размер компании: 51-200».
6. **Route** выбирает сегмент (`smb` или `enterprise`) и менеджера: повтор — тому же, новый — следующему по кругу среди активных менеджеров сегмента. Дисквалифицированные (соискатель, студент, спам, конкурент, нам что-то продают) никому не назначаются.
7. **Write CRM** пишет строку. Если таблица не приняла запись — вся заявка уходит в чат отдела, чтобы не потерялась.
8. **Notify** — карточка менеджеру в Telegram: баллы с причинами, суть, вопросы на звонок, флаги. Горячие лиды, лиды без менеджера и лиды «проверьте вручную» дублируются в чат отдела.
9. **Clarify Email** — если включено: тёплому лиду с почтой уходит письмо с вопросами от модели, чтобы менеджер звонил уже с ответами.

## Почему модель не ставит баллы сама

Модель хорошо понимает текст, но плохо держит шкалу: сегодня «7 из 10», завтра за то же «8». Поэтому модель отвечает на узкие вопросы с фиксированными вариантами (`high` / `medium` / `low`, размер из списка), а баллы, пороги и маршрутизацию считает код. Шкала стабильна, каждое число объяснимо, а рубрику вы меняете в Config без правки инструкции.

## Что если модель не ответила

Агент не останавливает конвейер: Score считает баллы только по фактам формы, ставит флаг «проверьте вручную», лид всё равно попадает в CRM и к менеджеру, а карточка — в чат отдела.
