# Evals: как проверять агента

Evals — набор тестовых заявок с ожидаемой оценкой. Прогоняйте перед запуском, после правки `offer`, `ideal_customer`, рубрики или инструкции.

## Запуск

```bash
python3 evals/run_evals.py \
  --url 'https://ВАШ-N8N/webhook/lead-qualification' \
  --token ВАШ_AGENT_TOKEN \
  --debug-token ВАШ_DEBUG_TOKEN
```

Ключи: `--only id1,id2`, `-v` (печатать оценку), `--report evals/report.json`, `--min-pass 0.9`. Python 3.8+, без пакетов. `--debug-token` обязателен: без него агент отвечает форме только `{ok, lead_id}`.

**Прогон настоящий:** заявки попадают в лист `Leads`, менеджеры получают карточки, уточняющие письма уходят, если включены. Запускайте на тестовой таблице и с тестовыми `chat_id` в `owners`, `clarify_by_email: false`. Домены в наборе содержат случайную строку прогона, поэтому повторный прогон не примет свои же заявки за дубли.

## Что в наборе

`evals/dataset.jsonl` — 16 случаев под демо-описание в Config (B2B-компании, которым нужна автоматизация продаж):

| Группа | Что проверяем |
|---|---|
| уровни | ясный B2B-запрос с бюджетом → горячий; интерес без деталей; «цена?» с gmail → холодный; маленький клиент |
| дисквалификация | соискатель, студент, нам продают SEO, спам, конкурент изучает цены |
| сегменты | холдинг на 2500 человек → enterprise |
| дубли | повторная заявка того же человека; вторая заявка той же компании по домену |
| прочее | попытка управлять оценкой через текст, заявка на английском, без сайта с корпоративной почтой, действующий клиент |

## Под свой бизнес

1. Перепишите `offer` и `ideal_customer` в Config.
2. Возьмите 20–30 реальных заявок за последние месяцы с известным исходом: купили, не купили, мусор. Уберите персональные данные и замените домены на `…-{rnd}.example`.
3. Для купивших ожидайте `tier_in: ["hot","warm"]`, для мусора — `disqualified` и нужный флаг.
4. Если рубрика расходится с реальностью — меняйте веса в Config, а не инструкцию.

## Формат случая

Описан в начале `evals/run_evals.py`: `tier_in`, `score_min`, `score_max`, `segment`, `fit_in`, `intent_in`, `size_in`, `flags_include`, `flags_exclude`, `owner_set`, `duplicate`.

## Как мы проверяли набор

Воркфлоу запускался в n8n 2.48 против подменных Google Таблиц, Telegram, почты и моделей — отдельно с OpenAI и с Anthropic, с локальным сайтом лида, 26 проверок: изучение двух страниц сайта, отказ в неверной оценке и приём исправленной, баллы с причинами, строка CRM, карточки менеджеру и отделу, дубли, дисквалификация, распределение по кругу, сегмент enterprise, отказ открыть чужой и внутренний адрес, отсутствие оценки модели, уточняющее письмо, ловушка для ботов, заявка без контакта, неверный токен, двойной клик, ответ 202 форме до оценки, сбой записи в CRM. Логика узлов Code покрыта ещё 22 тестами.

Как настоящая модель оценивает ваших лидов, мы проверить не можем — для этого ваш прогон evals.
