# MCP: Google Calendar

MCP-сервер, с которым AI-агент находит свободное время в Google Календаре и создаёт встречу только после явного «да» клиента. Без двойных записей и без сюрпризов.

## Что делает

- **Показывает только реально свободные слоты.** Учитывает занятость в одном или нескольких календарях, рабочие часы по дням недели, перерыв между встречами, минимальный срок записи («не раньше чем через 2 часа») и горизонт («не дальше 30 дней»).
- **Записывает в два шага.** `propose_event` проверяет время и возвращает вопрос, который агент показывает клиенту дословно: «Записываю: «Встреча: Анна», вт 25.11 10:00–10:30 (Europe/Kyiv), приглашение придёт на anna@example.com. Подтверждаете?». Событие появляется только после `confirm_event` с ответом клиента.
- **Проверяет, что ответ — это «да».** «Да», «подтверждаю», «записывайте» — запись. «Нет, давайте другое время», «а можно в среду?», «да, но не в это время» — отказ, ничего не записано.
- **Проверяет слот ещё раз перед записью.** Если пока клиент думал, время заняли, сервер не запишет и скажет агенту предложить другое.
- **Не создаёт дублей.** Повторное подтверждение возвращает уже созданное событие; у каждого события метка подготовки, по которой сервер его находит.
- **Подтверждение живёт 15 минут** (настраивается). Потом время нужно проверить и спросить заново.
- **Ничего не удаляет и не переносит**: таких инструментов в сервере нет.

## Что внутри

- `server/calendar_mcp.py`, `server/mcp_lite.py` — сервер. Python 3.9+, без пакетов.
- `server/get_refresh_token.py` — получить доступ к календарю один раз, через браузер.
- `config/calendar.example.json` — календари, часовой пояс, рабочие часы, правила записи.
- `rules/confirmation-rule.md` — правило подтверждения: что считается «да» и почему записи без него не будет.
- `checks/test-dialogue.md` — тестовый диалог с ожидаемыми вызовами.
- `clients/` — конфиги для Claude Code, Claude Desktop и Cursor.
- `docs/` — устройство, настройка Google, клиенты, безопасность.

## Как мы проверяли

Сервер проверен против подменных Google OAuth и Calendar API, через stdio и HTTP: 15 сценариев. Среди них занятый час и перерыв вокруг него, предложение занятого времени, три ответа, которые не «да», неизвестная подготовка, создание события с приглашением, повторное подтверждение без дубля, слот, занятый между вопросом и ответом, минимальный срок записи, просроченный refresh token. Скрипт `get_refresh_token.py` проверен на подменном OAuth-сервере: PKCE S256, offline-доступ, нужные права.

**Что мы не проверяли:** настоящий аккаунт Google — подменный API собран по справочнику Calendar API v3; как конкретная модель ведёт диалог — для этого `checks/test-dialogue.md`; интерфейсы Claude Desktop и Cursor.

## Что нужно

- Python 3.9 или новее. На Windows ещё `pip install tzdata`.
- Аккаунт Google с календарём и проект в Google Cloud (бесплатно).
- MCP-клиент: Claude Desktop, Claude Code, Cursor, n8n.
