# Как это работает

## Инструменты

| Инструмент | Что делает | Меняет календарь |
|---|---|---|
| `find_free_slots` | свободные слоты на период до 14 дней | нет |
| `propose_event` | проверяет время, готовит запись, возвращает вопрос подтверждения | нет |
| `confirm_event` | создаёт событие после «да» клиента | да |
| `cancel_proposal` | отменяет подготовку, если клиент передумал | нет |
| `list_events` | ваши события за период: время и название | нет |

Правило подтверждения — `rules/confirmation-rule.md`.

## Как считаются свободные слоты

Для каждого дня периода:
1. рабочее окно из `working_hours` (`null` — выходной);
2. начала встреч с шагом `slot_minutes` внутри окна; встреча должна закончиться до конца окна;
3. занятость из всех `busy_calendars`, расширенная на `buffer_minutes` с каждой стороны;
4. отбрасываются слоты раньше `min_notice_hours` от текущего момента и дальше `max_days_ahead`.

Пример: окно 09:00–18:00, шаг 30 минут, перерыв 15 минут, в календаре встреча 10:00–11:00. Слоты по 30 минут: 09:00, (09:30 — нет: до 10:00 нужен перерыв), …, (10:30 и 11:00 — нет), 11:30, 12:00 и дальше.

## Настройки calendar.json

| Поле | Что это | По умолчанию |
|---|---|---|
| `calendar_id` | календарь, куда пишутся встречи | `primary` |
| `busy_calendars` | календари, занятость которых учитывается | `[calendar_id]` |
| `timezone` | часовой пояс записи (IANA: `Europe/Kyiv`, `Europe/Warsaw`) | `Europe/Kyiv` |
| `working_hours` | окна по дням: `mon`…`sun`, `["09:00", "18:00"]` или `null` | — |
| `slot_minutes` | шаг между возможными началами | 30 |
| `default_duration_minutes` | длительность, если агент её не указал | 30 |
| `max_duration_minutes` | максимум длительности | 120 |
| `buffer_minutes` | перерыв до и после занятых встреч | 0 |
| `min_notice_hours` | минимум до начала встречи | 2 |
| `max_days_ahead` | на сколько дней вперёд можно записать | 30 |
| `proposal_minutes` | сколько живёт подготовленная запись | 15 |
| `title_template` | название события; `{name}` — имя клиента, `{topic}` — тема | `Встреча: {name}` |
| `description_footer` | последняя строка описания события | — |
| `send_updates` | приглашения: `all` — всем участникам, `none` — никому | `all` |
| `data_dir` | папка с подготовленными записями | `data` |

## Что попадает в событие

- название по `title_template`;
- описание: тема, имя клиента, ответ клиента на вопрос подтверждения дословно, `description_footer`;
- участник — клиент, если агент передал email; ему уходит приглашение Google;
- скрытая метка подготовки (`extendedProperties.private.proposal`) — по ней сервер находит событие при повторном подтверждении.

## Состояние

`data/calendar-state.json` — подготовленные записи за последние сутки. Удалять можно в любой момент: созданные события остаются в календаре, неподтверждённые подготовки пропадают.
