# Безопасность

## Что агент может и чего не может

| Может | Не может |
|---|---|
| видеть занятость календарей из `busy_calendars` | видеть описания и участников чужих встреч в `find_free_slots` |
| видеть время и названия ваших событий (`list_events`) | менять, переносить и удалять события |
| создать событие после подтверждения клиента | создать событие без подготовки, по старой подготовке или дважды |
| | менять доступы к календарю, создавать календари |

`list_events` показывает названия ваших встреч. Если агент общается с внешними клиентами — уберите этот инструмент в клиенте (в n8n: Tools to Include → Selected), чтобы агент не пересказал клиенту ваше расписание.

## Токены

- `GOOGLE_CLIENT_SECRET` и `GOOGLE_REFRESH_TOKEN` — в переменных окружения или менеджере секретов, не в `calendar.json` и не в репозитории.
- Refresh token даёт доступ к событиям всех ваших календарей в пределах двух прав. Утёк — отзовите доступ на myaccount.google.com/permissions и получите новый.
- В режиме HTTP без `MCP_HTTP_TOKEN` сервер слушает только `127.0.0.1`. С токеном проверяет `Authorization: Bearer …` и отклоняет запросы с чужим `Origin`.

## Данные

- `data/calendar-state.json` хранит подготовленные записи за сутки: время, имя и email клиента, тему.
- Имя, email и ответ клиента попадают в событие Google и в приглашение клиенту.
- Время и названия событий уходят провайдеру модели, когда агент вызывает `list_events` или видит занятые слоты.

## Ошибки модели

| Риск | Что защищает |
|---|---|
| модель записала без вопроса | без `propose_event` нет `proposal_id`; подтверждение вызова в клиенте MCP |
| модель неправильно поняла ответ «да, но…» | проверка ответа на сервере: оговорки → отказ |
| двойная запись | повторная проверка занятости и метка подготовки |
| запись на неудобное время | рабочие часы, перерыв, минимальный срок — на сервере |
| модель подставила «да» вместо ответа клиента | подтверждение вызова в Claude Desktop и Claude Code; в n8n — убрать `confirm_event` |
