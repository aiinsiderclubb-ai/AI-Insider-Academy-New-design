# Правило подтверждения

**Событие в календаре появляется только после того, как клиент сам ответил согласием на конкретный вопрос с датой, временем и названием.**

## Как это устроено

```
find_free_slots ──► агент предлагает 2–3 варианта ──► клиент выбирает
       │
propose_event ──► сервер проверяет время, ничего не пишет,
       │          возвращает confirmation_question и proposal_id
       │
агент показывает confirmation_question дословно ──► клиент отвечает
       │
confirm_event(proposal_id, ответ клиента дословно)
       │
сервер: ответ — однозначное «да»? подготовка не старше 15 минут?
        время всё ещё свободно? такого события ещё нет?
       │
       └─► событие + приглашение клиенту
```

Правило держится на трёх вещах, а не на одной инструкции модели:

1. **Сервер.** Без `propose_event` нет `proposal_id`, без него `confirm_event` не работает. `confirm_event` проверяет текст ответа, срок подготовки и занятость.
2. **Инструкция агенту.** Сервер при подключении передаёт клиенту правило: показать вопрос дословно и не вызывать `confirm_event`, пока клиент не ответил.
3. **Клиент MCP.** `confirm_event` помечен как меняющий данные. Claude Desktop и Claude Code спрашивают вас перед каждым его вызовом, если вы не разрешили его навсегда.

## Что считается «да»

Ответ начинается с согласия: да, ага, ок, окей, подтверждаю, записывайте, запишите, верно, всё верно, согласен, согласна, давайте, конечно, yes, ok, sure, confirm, correct.

И в ответе нет слов, которые меняют смысл: нет, «не …», отмен…, передумал, другое, другой, позже, no, not, cancel, wait, change.

| Ответ клиента | Результат |
|---|---|
| «Да» | запись |
| «Да, записывайте» | запись |
| «Ок, верно» | запись |
| «Нет, давайте другое время» | отказ |
| «а можно в среду?» | отказ: не начинается с согласия |
| «Да, но не в это время» | отказ: «не …» |
| «Давайте позже решим» | отказ: «позже» |

Проверка нарочно строгая: если клиент ответил двусмысленно, агенту лучше переспросить, чем записать не то.

## Чего правило не гарантирует

Сервер проверяет текст, который ему передал агент. Если модель подставит «да» вместо настоящего ответа клиента, сервер этого не увидит. Защита от этого — третий пункт: подтверждение вызова в клиенте MCP. В n8n такого подтверждения нет; если агент работает в n8n без человека, держите его в «только предлагать»: уберите `confirm_event` из разрешённых инструментов узла MCP Client (Tools to Include → Selected).

## Ответ клиенту после записи

`confirm_event` возвращает время, название и ссылку на событие. Агент сообщает клиенту время и что приглашение придёт на почту, если её указали. Ссылку на событие показывать клиенту не нужно: она открывается только у владельца календаря.
