# Настройка Notion и notion.json

## Подключение (internal connection)

1. app.notion.com/developers/connections → новое внутреннее подключение для рабочего пространства.
2. Возможности (capabilities):
   - **Read content** — нужен для поиска и чтения;
   - **Insert content** — нужен для `append_row`;
   - **Update content** — не нужен, выключите;
   - доступ к информации о пользователях — не нужен.
3. Токен (`ntn_…`) — в переменную окружения `NOTION_TOKEN`. В `notion.json` его не пишите.

## Доступ к базам

Подключение видит только страницы и базы, к которым его добавили: в базе `•••` → **Add connections**. Это первая линия защиты. Список баз в `notion.json` — вторая: даже если подключение случайно добавят к лишней странице, сервер не будет в ней искать.

Подключение, добавленное к странице, видит и все вложенные в неё страницы и базы. Добавляйте его к самим базам, а не к родительской странице раздела.

## ID источника данных

В Notion с API 2025-09-03 у базы (database) может быть несколько источников данных (data sources). Сервер работает с источниками.

В базе: `•••` → **Manage data sources** → у нужного источника **Copy data source ID**. Если источник один — он и нужен.

## notion.json

```json
{
 "knowledge": [
  {"name": "FAQ клиентов", "data_source_id": "…", "text_properties": ["Ответ", "Теги"]}
 ],
 "target": {
  "name": "Заявки от агента",
  "data_source_id": "…",
  "columns": {
   "Название": {"required": true, "max_length": 200},
   "Тема": {"required": true},
   "Email": {},
   "Комментарий": {"max_length": 2000},
   "Статус": {"fixed": "Новая"}
  },
  "dedupe_column": "Название"
 },
 "min_score": 0.3,
 "max_rows_per_source": 500,
 "cache_minutes": 5,
 "page_chars": 6000
}
```

| Поле | Что это |
|---|---|
| `knowledge[].text_properties` | колонки, по которым кроме названия идёт поиск. Названия — точно как в Notion |
| `target.columns` | колонки, которые агент может заполнять. Остальных колонок для него нет |
| `required` | без значения строка не запишется |
| `max_length` | длиннее — обрежется (для текстовых колонок) |
| `fixed` | значение ставит сервер, агент колонку не видит. Для Select и Status — точное название варианта |
| `dedupe_column` | колонка, по которой проверяются дубли: Title, Text, Email, Phone или URL. Пусто — без проверки |
| `min_score` | порог поиска 0–1. Чаще «не нашёл», хотя статья есть, — снизьте до 0.2 |
| `max_rows_per_source` | сколько строк читать из каждой базы знаний |
| `cache_minutes` | как долго держать прочитанные базы в памяти |
| `page_chars` | максимум символов статьи в `read_page` |

Без записи: удалите блок `target` — `describe_target` и `append_row` будут отвечать, что таблица не настроена.

## Как писать базу знаний

- Одна статья — один вопрос. Название — как спросит человек.
- В «Теги» — синонимы и разговорные слова: «вернуть, возврат, обмен, не подошло».
- Цифры и условия — в колонке «Ответ» или в начале статьи: поиск смотрит колонки, а не весь текст страницы. Весь текст агент получает через `read_page`.
