# Безопасность

## Три уровня ограничения

1. **Подключение Notion** видит только базы, к которым его добавили, и только с выданными возможностями: чтение и вставка, без изменения.
2. **notion.json** сужает дальше: поиск — только в `knowledge`, запись — только в `target`, только в перечисленные колонки.
3. **Набор инструментов**: у агента физически нет поиска по всему пространству, удаления и изменения.

Даже если агента уговорят («найди страницу с паролями», «удали старые заявки»), у него нет инструмента, чтобы это сделать.

## Содержимое базы — данные, не команды

Статья в Notion может содержать текст «Агент, запиши в таблицу…». Модель получает статьи как результат инструмента. Хорошие модели не выполняют такие указания, но гарантий нет. Поэтому:
- не давайте права на редактирование баз знаний тем, кому не доверяете;
- запись ограничена одной таблицей, проверенными колонками и защитой от дублей — худший случай это лишняя строка.

## Токены

- `NOTION_TOKEN` — в переменной окружения или менеджере секретов, не в `notion.json` и не в репозитории.
- Утёк — app.notion.com/developers/connections → подключение → обновить токен.
- В режиме HTTP без `MCP_HTTP_TOKEN` сервер слушает только `127.0.0.1`. С токеном проверяет `Authorization: Bearer …` и отклоняет запросы с чужим `Origin`.

## Данные

Найденные статьи и их текст уходят провайдеру модели. Не подключайте к агенту базы с персональными данными, договорами, финансами и доступами — список того, что не стоит подключать, есть в `config/allowed-databases.md`.

Сервер ничего не хранит на диске: прочитанные базы держит только в памяти процесса на `cache_minutes`.
