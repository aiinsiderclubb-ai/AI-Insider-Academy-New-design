# n8n

В n8n MCP-серверы подключаются к узлу AI Agent через узел **MCP Client Tool**. Он работает только по сети (HTTP Streamable). Локальные серверы, которые запускаются командой, нужно поднимать в режиме HTTP.

`clients/n8n-agent-mcp.n8n.json` — готовый воркфлоу: чат → AI Agent → OpenAI + три узла MCP Client (`db`, `github`, `hubspot`). Workflows → Import from File.

## Имена узлов

n8n добавляет имя узла MCP Client к названиям инструментов: узел `db` даёт инструменты `db_execute_sql` и `db_search_objects`. Поэтому узлы названы коротко. Так модель не путает инструменты разных серверов.

## Postgres (DBHub) в режиме HTTP

DBHub по умолчанию слушает все сетевые интерфейсы без пароля. Для n8n обязательно задайте токен и ограничьте адрес:

```bash
docker run -d --name dbhub --network ВАША_СЕТЬ_N8N \
  -v /путь/к/configs/dbhub.toml:/dbhub.toml:ro \
  -e AGENT_DB_PASSWORD=... -e DBHUB_AUTH_TOKEN=длинная-случайная-строка \
  node:22-slim npx -y @bytebase/dbhub@2 --config /dbhub.toml --transport http --port 8080 --allowed-hosts dbhub
```

- `DBHUB_AUTH_TOKEN` — DBHub отвечает 401 на запросы без `Authorization: Bearer …`;
- порт наружу не публикуется (нет `-p`) — DBHub доступен только n8n внутри сети Docker;
- `--allowed-hosts dbhub` — DBHub принимает запросы по имени контейнера.

Если n8n не в Docker: `npx -y @bytebase/dbhub@2 --config ./dbhub.toml --transport http --host 127.0.0.1 --port 8080` с той же переменной `DBHUB_AUTH_TOKEN`.

В узле `db`: Endpoint `http://dbhub:8080/mcp`, Authentication — **Bearer Auth**, токен = `DBHUB_AUTH_TOKEN`.

## GitHub

Узел `github`: Endpoint `https://api.githubcopilot.com/mcp/readonly`, Bearer Auth = fine-grained токен GitHub.

## HubSpot и Slack

Узел `hubspot` (или `slack`): Authentication — **MCP OAuth2**. Новый ключ: Client ID и Client secret из MCP-коннектора HubSpot или Slack-приложения; в коннектор или приложение добавьте Redirect URL, который n8n показывает в окне ключа. Нажмите Connect и войдите.

## Лишние инструменты

Tools to Include:
- **All** — все инструменты сервера;
- **Selected** — только перечисленные (например, для HubSpot только чтение: `search_crm_objects`, `get_crm_objects`, `get_user_details`);
- **All Except** — все, кроме перечисленных.

В n8n нет подтверждения вызова человеком — агент выполняет всё, что разрешено. Для автоматизаций без присмотра оставляйте только чтение.

## Что мы проверяли

Этот воркфлоу (узел `db`) мы запускали в n8n 2.48 против DBHub 2.0.0 в режиме HTTP с токеном и Postgres 17. Агент получил ответ на SELECT, а DELETE был отклонён режимом только чтения; данные не изменились. Модель в проверке была подменной — она вызывала инструменты по сценарию, — поэтому проверялась связка n8n ↔ MCP ↔ база, а не качество ответов модели. Узлы `github` и `hubspot` мы не подключали к настоящим аккаунтам.
