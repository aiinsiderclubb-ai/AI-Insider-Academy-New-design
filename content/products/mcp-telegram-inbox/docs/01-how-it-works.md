# Как это работает

```
рабочий чат ──► Telegram ──getUpdates──► сервер telegram-inbox ◄──MCP──► агент (Claude, Cursor, n8n)
                                             │  хранит сообщения               │
                                             │  в data/inbox-state.json        │
                                             ├──► CRM (вебхук): лид            │
                                             └──► чат менеджера: эскалация     │
```

MCP — протокол, по которому AI-агент вызывает инструменты внешних систем. Сервер даёт агенту пять инструментов и сам выполняет правила, которые нельзя доверять модели.

## Инструменты

| Инструмент | Что делает | Меняет что-то снаружи |
|---|---|---|
| `fetch_new_messages` | забирает новые сообщения у Telegram, сохраняет только разрешённые чаты | нет |
| `list_messages` | сохранённые сообщения: по умолчанию необработанные за 48 часов, с пометками правил | нет |
| `create_lead` | заводит лид в CRM по сообщениям клиента | да: запись в CRM |
| `mark_messages` | помечает сообщения: ignored, done или lead_external (лид заведён в другой системе) | нет |
| `escalate` | отправляет сообщения менеджеру с причиной и пересказом | да: сообщение в Telegram |

У каждого инструмента есть аннотации MCP (`readOnlyHint`, `destructiveHint`). По ним клиенты решают, когда спрашивать подтверждение. Claude Desktop и Claude Code по умолчанию спрашивают перед вызовом инструментов, которые что-то меняют.

## Статусы сообщения

```
new ──create_lead──► lead
    ──escalate────► escalated
    ──mark_messages► ignored / done / lead_external
```

`list_messages` по умолчанию показывает только `new` — агент не разбирает одно и то же дважды. История хранится `retention_days` дней (по умолчанию 14), потом удаляется.

## Что проверяет сервер, а не модель

- Сообщение есть в хранилище — id нельзя придумать.
- Телефон или email из `create_lead` есть в тексте этих сообщений: совпадение последних 9 цифр телефона или точный email.
- По сообщению ещё не заведён лид.
- Не больше `max_leads_per_10_minutes` лидов за 10 минут.
- Эскалация одного сообщения отправляется один раз.
- CRM ответила успехом — иначе сообщение остаётся `new`.

## Откуда берутся сообщения

Сервер использует метод Bot API `getUpdates`: Telegram хранит новые сообщения для бота до 24 часов и отдаёт каждое один раз. Поэтому:

- разбирайте чат хотя бы раз в сутки — то, что старше суток, Telegram уже не отдаст;
- у этого бота не должно быть вебхука и другой программы, которая тоже читает `getUpdates`. Если бот уже работает в другом сервисе, создайте для агента отдельного;
- бот видит только сообщения, написанные после того, как его добавили в чат и выключили Privacy Mode.

## Где хранится состояние

`data/inbox-state.json` рядом с файлом настроек: позиция чтения и сохранённые сообщения со статусами. Удалите файл — сервер начнёт с нуля и прочитает только то, что Telegram ещё не отдавал.
