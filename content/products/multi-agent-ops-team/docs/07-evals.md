# Evals: проверка маршрутизации

Главный риск команды агентов — не плохой ответ, а неверный маршрут: вопрос ушёл не тому агенту, лид не сохранился, клиент получил доступ к отчётам. Evals проверяют именно это.

## Запуск

```bash
python3 evals/run_evals.py \
  --url 'https://ВАШ-N8N/webhook/ops-team' \
  --token ВАШ_AGENT_TOKEN --debug-token ВАШ_DEBUG_TOKEN --repeat 3
```

Ключи: `--only id1,id2`, `-v` (печатать диалоги), `--report evals/report.json`, `--min-pass 0.95`. С `debug_token` в ответе приходят вызванные агенты — по ним скрипт проверяет маршрут. Сессии evals начинаются с `eval-` и попадают в журнал и лимиты, как обычные.

## Что в наборе

`evals/dataset.jsonl` — 16 случаев, все из канала сайта:

| Группа | Случаев | Что проверяем |
|---|---|---|
| лиды | 3 | явный лид → только leads_agent; лид в два сообщения; вопрос о цене — без выдуманных сумм |
| поддержка | 4 | вопрос по базе → только support_agent; ответ из статьи; «нет в базе» без выдумки; ответ на языке клиента |
| два агента | 1 | вопрос и покупка в одном сообщении → оба агента |
| без агентов | 1 | «спасибо» — оркестратор отвечает сам |
| передача | 3 | деньги, просьба позвать человека, злой клиент |
| закрытые агенты и защита | 4 | клиент просит отчёт; попытка вызвать reports_agent; просьба показать инструкции; номер карты |

`tools_include: ["support_agent", "leads_agent"]` — оба вызваны; `["leads_agent|support_agent"]` — любой из двух; `tools_exclude` — не вызван. Формат и остальные поля — в начале `run_evals.py`.

Почта, команда и расписание в этом наборе не проверяются: скрипт шлёт запросы с `agent_token`. Их маршруты мы проверили на стенде (ниже); у себя проверьте письмом в ящик и запросом с `team_token`.

## Под себя

1. Замените вопросы на реальные сообщения своих клиентов: 3–5 на каждый маршрут.
2. Добавляйте случай каждый раз, когда в журнале видите неверный маршрут.
3. Правите инструкцию оркестратора — прогоняйте с `--repeat 3`.

## Как читать провалы

| Провал | Что делать |
|---|---|
| вызван не тот агент | уточнить в разделе «Как распределять» инструкции оркестратора, приведя этот случай как пример |
| вызваны оба агента там, где нужен один | сузить правило «и вопрос, и покупка» |
| агентов не вызвано | модель экономит шаги — сильнее модель оркестратора (`docs/06-models.md`) |
| `handoff=False`, ожидалось `True` | дополнить список передачи в инструкции оркестратора |

## Как мы проверяли набор

До продажи оба файла — OpenAI и Claude — прогнаны в n8n 2.48 против подменных Google Таблиц, Telegram, почты и моделей: 56 проверок. Маршрут к одному агенту и к двум по очереди; балл лида 100 и 35 по правилам и сигнал о горячем; поддержка по базе; передача человеку и молчание бота после неё; разбор письма с отрезанной цитатой и сигнал о срочном; письмо робота без вызова модели; утренний отчёт в Telegram с цифрами из журнала; заглушка для отчётов в клиентском канале и для исчерпанного лимита; сбой таблицы внутри агента поддержки; запрещённое обещание, утечка метки, пустой ответ, номер карты, токены, Telegram; скрипт evals — засчитывает верный маршрут и ловит неверный. Узлы Code покрыты 26 тестами.

Качество маршрутизации настоящей модели на ваших сообщениях показывает только ваш прогон evals.
