# Подбор и показ объектов

Этот файл — для вас и для настройки агента. Правила подбора выполняет код инструмента `search_listings` (узел Match Listings), правила показа — инструкция агента. Здесь оба набора описаны рядом, с примерами, и есть готовые вставки в инструкцию под разные агентства.

## Как инструмент подбирает

1. Только объекты со статусом `active`.
2. Тип сделки (`buy` / `rent`) и тип объекта — точное совпадение; `any` — любой тип.
3. Бюджет: цена не выше бюджета — подходит; до +10% — подходит с пометкой «выше бюджета на N%»; дороже — не показывается.
4. Комнаты: `2`, `2-3`, `3+`. Отличие на одну комнату — показывается с пометкой «просили …», без баллов; больше — не показывается.
5. Район: совпадение даёт баллы. Объекты других районов идут ниже, с пометкой «другой район: …». Если в нужном районе нет ни одного объекта, инструмент прямо говорит агенту сказать об этом клиенту.
6. Объект, с которым клиент пришёл (`listing_ref`), — всегда первым.
7. Сортировка: по баллам, при равенстве — дешевле выше. До трёх объектов.

У каждого объекта в ответе есть `why` — список причин. Это и есть «объяснимый подбор»: агент повторяет эти причины, а не придумывает свои.

## Как агент показывает

Правила из инструкции (`agent/system-prompt.md`, шаг 3):
- не больше трёх объектов за раз, по строке на объект;
- номер, что это, цена, почему подходит, ссылка;
- никаких деталей, которых нет в данных: этаж, ремонт, торг, «тихий район» — только если это есть в листе;
- в конце — один вопрос: «Посмотрим какой-то вживую?»

Пример хорошего ответа:

```
Нашёл два варианта на Печерске в вашем бюджете:
KV-101 — 2-комн. квартира, ул. Лескова, 9, 148 000 USD: в бюджете, 2 комнаты, Печерский. https://example.com/kv-101
KV-103 — 1-комн. квартира, Голосеевский, 69 000 USD: в бюджете, но 1 комната и другой район. https://example.com/kv-103
Хотите посмотреть KV-101 вживую?
```

Пример плохого — агент так не отвечает:

```
Есть отличная двушка на Печерске с панорамным видом, владелец готов немного уступить!
```

Здесь нет номера, придуман вид, обещан торг.

## Готовые вставки в инструкцию

Добавьте в раздел «Как ты работаешь» после шага 3, если подходит вашему агентству.

**Новостройки.** «Если в поле features есть срок сдачи дома, называй его. Не обещай сроки сдачи сверх указанных.»

**Аренда с животными.** «Если клиент с животными, спроси об этом до подбора и упомяни объекты, где в features есть "можно с животными". Об остальных не говори "можно" или "нельзя" — уточнит риелтор.»

**Премиум.** «Клиенту с бюджетом выше [сумма] сначала предложи разговор с риелтором (handoff_to_human с причиной "премиум-клиент"), затем подборку.»

**Инвесторы.** «Если клиент покупает для сдачи в аренду, не называй доходность и окупаемость: это считает риелтор. Передай с причиной "инвестиционный запрос".»

**Один город, много районов.** «Если клиент называет улицу или станцию метро, переведи её в район из этого списка: [список] — и передай в area.»

## Поля листа Listings

`listing_id | status | deal_type | property_type | city | area | address | rooms | area_m2 | price | currency | floor | description | url | agent_id | features`

- `listing_id` — короткий код вида `KV-101`: заглавные буквы, дефис, цифры. По такому шаблону Guard Out находит в ответе номера объектов.
- `status` — `active`, `reserved`, `sold`, `rented`. Показываются только `active`.
- `area` — район так, как его называют клиенты.
- `price` — число без пробелов и валюты.
- `agent_id` — `id` риелтора из Config: к нему идут просмотры этого объекта.
- `features` — короткие особенности через запятую: агент может их назвать.
