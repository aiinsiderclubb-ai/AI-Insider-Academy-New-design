# Как это работает

```
9:00 каждый день ─► Read Invoices ─► Plan Invoices ─► Assess & Draft (модель) ─► Check Draft
                                                                                   │
                                     Approval Card ◄── Cards ◄── Append Drafts ◄───┘
                                          │
            вы нажали кнопку или написали команду
                                          ▼
Telegram Trigger ─► Read for Telegram ─► Telegram Act ─► (Send Email) ─► Update Sheets ─► Log Activity ─► ответ в чат

Понедельник 9:30 ─► Read for Report ─► Weekly Report ─► Telegram

Preview Webhook ─► Preview Plan ─► Assess & Draft ─► Check Draft ─► JSON в ответ (ничего не сохраняется)
```

## Утро: черновики

1. **Plan Invoices** читает Invoices и Drafts и отбирает счета, которым пора напоминание: не закрыты, не оспорены, не на паузе, нет обещания на будущую дату, нет ждущего черновика, прошло не меньше `min_gap_days` с последнего письма, просрочка дошла до дня следующего шага. Для каждого считает риск по правилам и собирает факты для модели.
2. **Assess & Draft** — модель по инструкции `agent/draft-prompt.md` возвращает JSON: риск, причины, тему, текст.
3. **Check Draft** проверяет ответ. Риск модели принимается, только если он выше риска по правилам. Текст заменяется шаблоном нужного тона, если в нём нет номера счёта или точной суммы, есть угроза, упрёк, скидка или ссылка, или ответ не JSON. В конец письма добавляются `payment_details` и подпись.
4. Черновики сохраняются в Drafts со статусом `pending`, в Telegram приходит по карточке на каждый.

Ничего не отправляется до нажатия кнопки.

## Кнопка

**Telegram Act** принимает кнопку или команду только из чатов `approver_chat_ids`.
- **Отправить**: счёт проверяется ещё раз. Если его успели оплатить, оспорить, поставить на паузу или по нему есть обещание — письмо не уходит, черновик получает статус `cancelled`, вам приходит причина. Иначе — письмо по SMTP, черновик `sent`, у счёта растёт `stage` и обновляется `last_contact`.
- **Изменить**: бот просит прислать новый текст ответом на сообщение. Ответ заменяет текст, реквизиты и подпись добавляются, приходит новая карточка.
- **Пропустить**: черновик `skipped`. Следующий шаг по счёту придёт после `min_gap_days`.

Если SMTP не принял письмо — черновик `failed`, счёт не меняется, вам приходит ошибка.

## Понедельник: отчёт

Просрочка по возрасту долга, что оплачено за неделю по счетам, которым уходили напоминания, сколько писем отправлено и сколько ждут решения, обещания на неделю, нарушенные обещания, споры и пять самых рискованных счетов.

## Предпросмотр

`POST /webhook/recovery-preview` с `preview_token` — один счёт в теле, в ответ риск и письмо, ничего не сохраняется и не отправляется. Для evals и для проверки тона после правки инструкции.

## Где что хранится

Всё — в вашей таблице: счета, черновики со статусами, журнал решений. Агент можно перезапускать: он ничего не держит в памяти.
