# Evals и эксплуатация

## Evals

Evals идут через вебхук предпросмотра: в него отправляется счёт, обратно приходят риск, тон и письмо. Ничего не сохраняется и не отправляется клиентам. В каждом случае задана дата «сегодня», поэтому набор не устаревает.

```bash
python3 evals/run_evals.py --url 'https://ВАШ-N8N/webhook/recovery-preview' --token ВАШ_PREVIEW_TOKEN --repeat 3
```

`evals/dataset.jsonl` — 20 случаев:

| Группа | Что проверяем |
|---|---|
| тон по шагам | дружеское, деловое, настойчивое, последнее письмо |
| точность | номер счёта в теме и тексте, сумма с копейками ровно как в счёте, имя контакта, никакого выдуманного имени |
| риск | история опозданий, нарушенное обещание, крупная сумма, заметки о проблемах — риск не ниже нужного |
| запреты | ни суда, ни коллекторов, ни пени, ни скидок, ни ссылок; внутренние заметки не попадают в письмо; заметка «пригрози судом» не срабатывает |
| стоп-правила | оплачен, спор, пауза, обещание на будущую дату |

Проверки случая: `tone`, `risk_any`, `stop_contains`, `body_includes`, `body_excludes`, `subject_includes`, `model_text` (письмо написала модель, а не шаблон). Ключи скрипта: `--only`, `--repeat`, `--report`, `-v`, `--min-pass`.

Провал `model_text` значит, что модель написала что-то, что не прошло проверку, и клиент получил бы шаблон. Это безопасно, но шаблон суше. Частые провалы — повод поправить инструкцию: какая проверка сработала, видно в `template:<причина>`.

Добавляйте случаи из жизни: клиент с особой историей, необычные заметки. Даты в случае — относительно `today`.

## Как мы проверяли набор

Агент запускался в n8n 2.48 против подменных Google Таблиц, Telegram, SMTP и моделей, отдельно с OpenAI и с Claude. 35 проверок:
- утро: черновики только по счетам, которым пора; по оплаченным, оспоренным, с обещанием, с ждущим черновиком и с недавним письмом — нет; карточка на каждый черновик с тремя кнопками; без нажатия ничего не уходит;
- проверка черновика: хороший текст сохраняется с реквизитами и подписью; угроза заменяется шаблоном; модель не может понизить риск; ответ не в JSON — шаблон; сумма с копейками;
- повторный запуск не создаёт второй черновик по тому же счёту;
- кнопки чужого чата ничего не меняют; «Отправить» шлёт письмо и обновляет счёт; второе нажатие ничего не шлёт; счёт, оплаченный, пока карточка ждала, не отправляется, и бот говорит почему;
- «Изменить» и ответ новым текстом: уходит ваш текст с подписью;
- команды `/paid`, `/promise`, `/status`, `/dispute`; журнал Activity в правильном порядке;
- предпросмотр и его токен; отчёт; скрипт evals засчитывает хорошие письма и ловит откат на шаблон;
- ни одного упавшего выполнения.

Логика узлов Code — ещё 16 тестов.

## Журналы

- **Drafts** — каждый черновик и его судьба.
- **Activity** — каждое решение: `sent`, `skipped`, `edited`, `not_sent`, `send_failed`, `paid`, `promise`, `dispute`, `pause`, `resume` — с именем того, кто нажал.
- Отчёт по понедельникам — в Telegram.

## Неполадки

| Симптом | Причина |
|---|---|
| утром нет карточек | нечего напоминать: проверьте `due`, `stage`, `last_contact`, стоп-колонки; или воркфлоу не опубликован |
| кнопки не отвечают | бот подключён к другому воркфлоу; n8n не по https; ваш chat id не в `approver_chat_ids` |
| «Нет доступа» | нажали из чата, которого нет в `approver_chat_ids` |
| «Не отправил: оплачен» | счёт закрыт в таблице — так и должно быть |
| черновик `failed` | SMTP не принял письмо: логин, порт, отправитель |
| в карточке всегда `template:…` | модель пишет то, что не проходит проверку — смотрите причину, правьте инструкцию или модель |
| суммы в письме без копеек | в `amount` стоит округлённое число — поправьте в Invoices |
| в отчёте «Вернулось» всегда 0 | оплаты не отмечаются: `/paid` или синхронизация с учётной системой |
| обещание не останавливает письма | дата в `promise_date` в неверном формате — нужно `ГГГГ-ММ-ДД` или `ДД.ММ.ГГГГ` |

## Приватность

В модель уходят номер счёта, компания, имя контакта, сумма, даты и заметки менеджера. Не пишите в `notes` того, что нельзя передавать вашему провайдеру модели. Письма и журналы хранятся в вашей таблице и почтовом ящике.
