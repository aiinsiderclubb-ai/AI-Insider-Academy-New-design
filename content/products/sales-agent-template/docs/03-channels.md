# Каналы

## Сайт

`templates/chat-widget.html` — готовый виджет: кнопка в углу, окно переписки, история сессии в браузере. Вставьте блок перед `</body>` и замените две строки:

```js
var ENDPOINT = 'https://ВАШ-N8N/webhook/sales-agent';
var TOKEN = 'ВАШ_AGENT_TOKEN';
```

Ответ агента виджет показывает как текст, не как HTML: даже если модель вернёт разметку или скрипт, на странице он не выполнится.

**Про токен.** Токен лежит в коде страницы — его видит любой, кто откроет исходник. Он отсекает случайные запросы на найденный адрес, но секретом не является. Бюджет защищают лимиты: `rate_limit_*` на одного клиента и `daily_agent_runs` на всех. Если нужна строгая защита — поставьте между сайтом и n8n свой сервер, который проверяет пользователя и добавляет токен сам.

**CORS.** Узел Webhook принимает запросы с любых сайтов (`Allowed Origins: *`). Чтобы разрешить только свой домен, откройте Webhook → Options → Allowed Origins и впишите `https://ваш-сайт.com`.

## Telegram

Telegram Trigger подключается при публикации воркфлоу — отдельной настройки не нужно. Требования Telegram: n8n доступен по https, у одного бота — один адрес для обновлений. Если этот бот уже работает в другом воркфлоу, создайте для агента отдельного.

Боту можно писать в личку. В группах бот видит сообщения, только если ему выдать права администратора или выключить Privacy Mode в @BotFather.

Ответы в Telegram уходят как HTML с экранированием: символы `<`, `>`, `&` из ответа модели не ломают сообщение.

## API для любой системы

CRM, мобильное приложение, WhatsApp-бот — любой сервис может говорить с агентом через тот же вебхук.

**Запрос**

```
POST https://ВАШ-N8N/webhook/sales-agent
Content-Type: application/json
x-agent-token: ВАШ_AGENT_TOKEN          (или поле "token" в теле)

{
  "session_id": "crm-48213",            обязателен: 6–100 символов, буквы, цифры, : . _ -
  "message": "Нужна CRM на 5 человек",  обязателен
  "name": "Анна",                       необязательно
  "email": "anna@example.com",          необязательно; попадёт в лид и пригодится для КП
  "phone": "+380501112233"              необязательно
}
```

Один `session_id` — один диалог: память агента, лимиты и пауза после передачи считаются по нему.

**Ответ 200**

```json
{
  "reply": "Вот ссылка на оплату CRM Старт: https://pay.example.com/crm-start",
  "handoff": false,
  "session_id": "crm-48213",
  "payment_link": "https://pay.example.com/crm-start"
}
```

- `handoff: true` — диалог у менеджера, следующие сообщения бот не обрабатывает, а пересылает команде.
- `payment_link` или `booking_link` — если в этом ответе агент дал ссылку на оплату или на запись к менеджеру.
- С заголовком `x-agent-debug: ВАШ_DEBUG_TOKEN` в ответе появляются `tools` (какие инструменты вызваны и с чем) и `flags` (пометки защиты). Только для отладки и evals.

**Ошибки:** `401` — нет или неверный токен; `400` — неверный `session_id`.

Если ваша система знает клиента — передавайте имя, email и телефон: они попадут в лид, и агенту не придётся их спрашивать.

**Follow-up** пишет первым только тем, кому может: клиентам из Telegram — в Telegram, клиентам с сайта — на email, если включён `email_followups`. Клиентам из вашей системы через API follow-up не пишет: канал `web` без email пропускается.
