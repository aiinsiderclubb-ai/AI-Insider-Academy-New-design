# Квалификация, каталог и follow-up

## Баллы

`save_lead` считает баллы кодом — модель их только передаёт клиенту в виде следующего вопроса. Четыре части по 25 баллов:

| Часть | 25 | 15 | 10 | 5 | 0 |
|---|---|---|---|---|---|
| need — задача | названа | | | | неизвестна |
| budget — бюджет | число от `min_budget` | | число меньше или «не знаю» | | неизвестен |
| timeline — сроки | «сейчас», «срочно», «в этом месяце» | «в следующем месяце», «через 2 месяца», «квартал» | | «позже», «не знаю» | неизвестны |
| authority — решение | «я», «владелец», «директор» | | «вместе с партнёром», «согласуем» | | неизвестно |

Бюджет читается так, как пишут люди: «2k», «1 500 €», «около 2 тыс», «50 тысяч». Уровни: от `hot_score` (70) — горячий, от `warm_score` (40) — тёплый, ниже — холодный.

- Когда лид впервые становится горячим, в чат продаж приходит карточка: имя, контакт, задача, бюджет, сроки, кто решает.
- Если бюджет от `large_deal_budget`, агент получает указание передать сделку менеджеру.
- `save_lead` возвращает, чего не хватает, — агент спрашивает по одному вопросу за раз.

Этапы (`stage`): `new` → `qualifying` → `offer_sent` / `call_booked` → `won` / `lost`. Агент ставит этапы по ходу разговора; `won` и `lost` удобнее ставить менеджеру в таблице.

## Лист Leads

`session_id | channel | chat_id | name | email | phone | need | budget | timeline | authority | product_id | score | tier | stage | touches | last_touch_at | notes | updated | created`

Одна строка — один диалог. Повторный `save_lead` дополняет строку: пустые поля не затирают известные, заметки дописываются через `|`. Колонки менять местами нельзя — follow-up пишет счётчик касаний в колонки O и P.

## Каталог — лист Products

`id | name | description | price | currency | url | payment_link | tags | in_stock`

- `id` — латиницей, без пробелов: его агент передаёт в `send_offer`.
- `payment_link` — готовая ссылка на оплату (Stripe Payment Link, LiqPay, WayForPay, Tribute, страница корзины). Пусто — товар продаётся через КП или звонок.
- `tags` — слова, которыми клиенты описывают задачу: «crm продажи сделки менеджеры».
- `in_stock` — `да` или `нет`.

## Одобренные ответы — лист Facts

`id | topic | approved_answer | tags`

Сюда — всё, что агент может утверждать в ответ на возражения: условия теста, гарантии, сроки, кейсы с цифрами, сравнение с конкурентами, официальные скидки. Только правдивое и то, что вы готовы подтвердить. Демо-ответы в `templates/facts.csv` — пример формулировок, замените их своими.

Официальную скидку пишите как правило, а не обещание: «При оплате за год — минус 10%». Фраза «дадим скидку» в ответе агента сработает на запрет в Guard Out.

## Follow-up

Агент пишет первым тем, кто замолчал, — по правилам, которые проверяет код:

| Правило | Параметр Config |
|---|---|
| только лиды на этапах | `followup_stages` — по умолчанию `new`, `qualifying`, `offer_sent` |
| пауза перед касанием — с последнего сообщения клиента, последнего касания или создания лида | `followup_delays_hours` — 24, 72, 168 |
| не больше касаний, чем пауз в списке | 3 |
| не в тихие часы и не в выходные (время компании) | `followup_quiet_from`, `followup_quiet_to`, `followup_weekdays` |
| никогда — тем, кто в стоп-листе | лист `OptOut`: по сессии, chat_id, email или телефону |
| не больше сообщений за запуск | `followup_max_per_run` |
| куда | Telegram — клиентам из Telegram; email — клиентам с сайта, если `email_followups: true` |

Тексты — `followup_messages`, по одному на касание. `{name}` — имя клиента, `{product}` — название товара из каталога. Во втором тексте по умолчанию есть подсказка написать «стоп» — оставьте её.

Если клиент ответил — пауза считается заново от его сообщения, но счётчик касаний не обнуляется: всего за диалог не больше трёх напоминаний.

## Стоп-лист

«Стоп», «отписаться», «не пишите мне», «не беспокойте» (`optout_words`) — Guard In отвечает без модели (`optout_reply`) и добавляет строку в `OptOut`. Отвечать клиенту, если он сам напишет снова, агент продолжит — стоп-лист запрещает только писать первым.
