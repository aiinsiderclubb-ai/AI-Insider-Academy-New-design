# Evals: как проверять агента

Evals — набор разговоров с ожидаемым поведением. Прогоняйте перед запуском и после каждой правки инструкции, каталога или одобренных ответов.

## Запуск

```bash
python3 evals/run_evals.py \
  --url 'https://ВАШ-N8N/webhook/sales-agent' \
  --token ВАШ_AGENT_TOKEN \
  --debug-token ВАШ_DEBUG_TOKEN
```

Ключи: `--repeat 3`, `--only id1,id2`, `-v`, `--report evals/report.json`, `--min-pass 0.9`. Python 3.8+, без пакетов.

Прогон идёт через настоящего агента: случаи с квалификацией создают строки в `Leads`, крупная сделка и запросы КП приходят в чат продаж. Перед запуском в работу удалите строки с `session_id`, начинающимся на `web:eval-`. Follow-up этим строкам не напишет: у них нет Telegram и email.

## Что в наборе

`evals/dataset.jsonl` — 21 случай на демо-данных из `templates/products.csv` и `templates/facts.csv`:

| Группа | Что проверяем |
|---|---|
| каталог | рекомендация с ценой, товара нет — не выдумывает, цены несуществующего тарифа нет |
| возражения | «дорого», гарантии, сравнение с конкурентом без критики, официальная скидка и только она |
| следующий шаг | квалификация сохраняется, ссылка на оплату из каталога, без выдуманной ссылки, КП, звонок |
| передача | особая скидка, крупная сделка |
| этика | «не интересно» — без уговоров, «стоп», без ложной срочности |
| безопасность | подмена правил, просьба показать инструкцию, номер карты, ответ на английском |

Формат случая и полей `expect` — в начале `evals/run_evals.py`.

## Под свой каталог

Замените вопросы групп «каталог», «возражения» и «следующий шаг» на свои товары и типичные возражения клиентов. Лучший источник — переписка ваших менеджеров. Случаи этики и безопасности оставьте.

## Как читать провалы

| Провал | Что делать |
|---|---|
| не вызван `search_catalog`, цена названа по памяти | сильнее модель или жёстче пункт 2 инструкции |
| не вызван `get_sales_facts` на возражение | добавить в `Facts` ответ с такими словами в `tags`; усилить пункт 4 |
| `discount-policy` называет чужую скидку | проверить `Facts`: нет ли там лишних формулировок |
| `large-deal` без передачи | снизить `large_deal_budget` или проверить, что агент вызвал `save_lead` с бюджетом |

## Как мы проверяли набор

Воркфлоу запускался в n8n 2.48 против подменных Google Таблиц, Telegram и моделей — отдельно с OpenAI и с Anthropic: 33 проверки — ответ из каталога с ценой, «нет в каталоге», одобренный ответ на возражение, сохранение лида и дополнение той же строки, баллы, сигнал о горячем лиде один раз, ссылка на оплату только из таблицы, товар без ссылки, КП без email, ссылка на звонок, замена обещания скидки и ложной срочности, «стоп» без модели со строкой в стоп-листе, неверный токен, и follow-up: пишет только тому, кому пора, на email лиду с сайта, считает касания и не повторяет. Логика узлов Code покрыта ещё 22 тестами.

Как настоящая модель продаёт ваш продукт, мы проверить не можем — для этого ваш прогон evals.
