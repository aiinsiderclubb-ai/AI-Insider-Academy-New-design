# Эксплуатация

## Каждый день

- Чат продаж: горячие лиды, ссылки на оплату, запросы КП, звонки, передачи — разбирайте их в рабочее время.
- Лист `Leads`: отсортируйте по `score`. Ставьте `won` и `lost` сами — так follow-up перестанет писать закрытым сделкам.

## Раз в неделю — журнал

Лист `Log`: время, сессия, канал, сообщение, ответ, инструменты, передача, пометки, ссылки. Смотрите:
- `forbidden_promise` — где агента тянуло пообещать скидку или срочность; добавьте в `Facts` честный ответ на этот вопрос;
- `get_sales_facts` без продолжения разговора — возражение, на которое нет хорошего ответа;
- `search_catalog` без следующего шага — клиенты ищут то, чего нет в каталоге;
- `injection` — попытки сломать агента;
- `service_error` — сбои таблицы или Telegram.

## Память диалога

Simple Memory хранит переписку в памяти n8n: после перезапуска агент не помнит начатые разговоры, но лид в `Leads` остаётся. Для режима очереди с несколькими воркерами замените Memory на Postgres Chat Memory или Redis Chat Memory с тем же Session Key.

## Приватность и рассылки

- В `Leads`, `Log` и модель попадают имя, контакты и то, что клиент рассказал о задаче и бюджете. Укажите это в политике конфиденциальности, определите срок хранения журнала.
- Follow-up — это сообщения первым. Пишите только тем, кто сам начал диалог; не добавляйте в `Leads` контакты из чужих баз. Стоп-лист соблюдается кодом.
- Email follow-up — коммерческие письма: проверьте требования вашей страны к согласию на рассылку.

## Изменения

- **Каталог и одобренные ответы** — в таблице, действуют сразу.
- **Пороги, ссылки, follow-up** — в Config.
- **Инструкция** — правьте `agent/system-prompt.md`, затем перенесите в узел AI Agent → Options → System Message, не трогая ссылки на Config в двойных фигурных скобках. После правки — evals.

## Неполадки

| Симптом | Причина |
|---|---|
| вебхук отвечает 401 | заглушка в `agent_token` или неверный токен |
| 404 на Production URL | воркфлоу не опубликован |
| агент говорит «каталог недоступен» | неверный `spreadsheet_id`, нет листа `Products`, у Google-ключа нет доступа; в журнале `service_error` |
| follow-up не пишет | не опубликован; тихие часы или выходной; этап не из `followup_stages`; клиент с сайта без email или `email_followups: false`; лид в стоп-листе; касания исчерпаны |
| follow-up пишет закрытой сделке | этап в `Leads` не `won` или `lost` |
| «горячий лид» приходит снова | строку в `Leads` удалили — для агента это новый лид |
