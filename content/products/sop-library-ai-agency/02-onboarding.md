# Старт работы с клиентом

## O-01. Договор и первая оплата

**Зачем:** Начать работу только после подписи и оплаты.

**Когда:** Клиент согласовал предложение.

**Отвечает:** Менеджер по продажам

### Шаги

1. Перенести согласованный объём в описание работ с критериями приёмки.
2. Отправить договор, описание работ и счёт на первую часть одним письмом.
3. После оплаты — сообщить команде и создать проект в трекере.
4. Передать руководителю проекта карточку клиента: заметки, предложение, контакты.

### Готово, когда

- [ ] Подписанный договор и описание работ
- [ ] Поступила первая оплата
- [ ] Проект создан, руководитель назначен

### Частые ошибки

- Начинать «пока согласуют договор»

## O-02. Сбор доступов

**Зачем:** Получить доступы безопасно и за один заход.

**Когда:** Проект создан.

**Отвечает:** Руководитель проекта

### Шаги

1. Отправить клиенту список доступов с объяснением, зачем каждый.
2. Попросить отдельные учётные записи или API-ключи с минимальными правами, а не личный пароль руководителя.
3. Принимать секреты только через менеджер паролей или одноразовую ссылку, не в мессенджере.
4. Проверить каждый доступ в день получения.
5. Записать в реестр: система, уровень прав, кто выдал, когда отозвать.

### Готово, когда

- [ ] Все доступы проверены
- [ ] Реестр доступов заполнен
- [ ] Ни одного пароля в переписке

### Частые ошибки

- Работать под личной учётной записью клиента
- Хранить ключи в заметках и таблицах

## O-03. Стартовая встреча

**Зачем:** Договориться о целях, ролях и порядке общения.

**Когда:** Доступы получены.

**Отвечает:** Руководитель проекта

### Шаги

1. Повестка: цель и метрика, объём, график, роли, порядок приёмки, канал связи.
2. Пройти процесс клиента по шагам и зафиксировать схему «как есть».
3. Собрать 20–30 реальных примеров входных данных.
4. Договориться о еженедельном статусе: день, время, формат.
5. Отправить итоги письмом в тот же день.

### Готово, когда

- [ ] Схема процесса согласована
- [ ] Примеры данных получены
- [ ] Ответственный со стороны клиента назван
- [ ] Итоги встречи отправлены

### Частые ошибки

- Не назначить ответственного с правом приёмки

## O-04. Карта процесса и техническое задание

**Зачем:** Зафиксировать, что строим, до того как строить.

**Когда:** Проведена стартовая встреча.

**Отвечает:** Инженер по автоматизации

### Шаги

1. Нарисовать процесс «как будет»: триггер, шаги, решения, исключения, выход.
2. Для каждого шага указать систему, данные на входе и выходе.
3. Отметить шаги, где решение остаётся за человеком.
4. Описать, что происходит при ошибке на каждом шаге.
5. Согласовать с клиентом письменно.

### Готово, когда

- [ ] Схема «как будет» согласована
- [ ] Список исключений и их обработка
- [ ] Список тестовых случаев

### Частые ошибки

- Начинать сборку по устному описанию
