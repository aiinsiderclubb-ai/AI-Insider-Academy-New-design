# Эксплуатация

## Первая неделя

Каждый день:

1. Прочитайте все сводки звонков в Telegram.
2. Прослушайте или прочитайте три звонка целиком: один удачный, один с переводом на человека, один оборванный.
3. Выпишите, где агент ошибся или звучал неестественно, — это материал для `docs/09-tuning.md`.
4. Сверьте записи в календаре с тем, что клиенты говорили в звонках.

Со второй недели — раз в два-три дня, с третьей — раз в неделю.

## Что смотреть

| Показатель | Где | Тревога |
|---|---|---|
| Доля звонков, закончившихся записью или передачей | Сводки, аналитика провайдера | Падает неделю к неделе |
| Доля переводов на человека | Аналитика провайдера | Выше трети — агент не справляется с типовыми запросами |
| Сообщения «Сбой инструмента» | Telegram | Любое |
| Сообщения «Ошибка воркфлоу» | Telegram | Любое |
| Длительность звонка | Аналитика | Резкий рост — агент зацикливается |
| Расходы | Панель провайдера | Выше расчёта из `sales/roi-calculator.csv` |

## Если агент перестал записывать

1. Проверьте Telegram: есть ли «Сбой инструмента» или «Ошибка воркфлоу».
2. В n8n откройте последние ошибочные запуски «Booking Tools».
3. Частые причины:
   - истёк доступ Google — переподключите учётные данные;
   - воркфлоу выключен после правки — включите;
   - изменился адрес n8n — обновите адрес в инструментах у провайдера;
   - сменили секрет в одном месте — он должен совпадать в n8n и у провайдера.
4. Выполните первый запрос из `tests/tool-payloads.md`: он покажет, отвечает ли бэкенд.

## Аварийное отключение

Самый быстрый способ — снять переадресацию у оператора или отвязать номер от агента в панели провайдера. Звонки пойдут на людей как раньше. Это должны уметь два человека; впишите их имена в `sales/client-handoff.md`.

## Изменения в расписании

| Что изменилось | Что сделать |
|---|---|
| Выходной, праздник | Добавить дату в `closed_dates` в Config или создать событие на весь день без специалиста |
| Отпуск одного специалиста | Создать события на его рабочее время и указать ему `staff_id` — см. ниже |
| Новая услуга или цена | Обновить `services` в Config, базу знаний в промпте и описание `service_id` в инструментах у провайдера |
| Новый пост | Добавить в `staff` и в `services[].staff`; обновить описание `staff_id` в инструментах |
| Новые часы работы | Обновить `hours` в Config и базу знаний |

После любой правки Config пройдите три теста: запись, перенос, отмена.

## Как закрыть время одному специалисту

Событие без `staff_id` закрывает время всем. Чтобы закрыть одному:

- проще всего — попросить администратора записать «клиента» с именем «Отпуск» через агента или запрос из `tests/tool-payloads.md`, указав `staff_id`;
- либо создать событие через API календаря с расширенным свойством `staff_id`.

Если специалисты часто работают по разным графикам, заведите каждому свой календарь и размножьте пару узлов Calendar — это доработка за пределами набора.

## Откат

- Перед каждой правкой воркфлоу сохраняйте копию: Download.
- Перед правкой промпта сохраняйте прежнюю версию с датой.
- Если после правки стало хуже — верните прежнюю версию, а не правьте поверх.
