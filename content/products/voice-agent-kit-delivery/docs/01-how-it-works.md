# Как это устроено

```
Клиент звонит                    или    n8n каждый день в 16:00 звонит сам
     │                                  клиентам с завтрашней доставкой без подтверждения
     │                                       │ (Confirmation Calls → Vapi или Retell)
Номер телефона ── провайдер голоса (Vapi, Retell или ElevenLabs)
                        │   распознаёт речь, ведёт диалог по промпту, говорит голосом
                        │
                        │  вызов инструмента: «найди заказ по этому номеру»
                        ▼
                  n8n: Order Tools ──────► Google Таблица заказов
                        │                  читает заказ, пишет подтверждение, адрес, интервал
                        ├──► Telegram операторов: новый адрес, перенос, просьба связаться
                        ▼
                  ответ агенту: данные заказа, свободные интервалы или результат

После звонка: провайдер ──► n8n: Call Summary ──► Telegram: сводка звонка
При сбое:     n8n: Error Alert ──► Telegram: что сломалось
```

## Четыре части

**1. Провайдер голоса.** Отвечает за разговор: слышит, понимает, говорит. Вы даёте ему промпт из `prompts/` и шесть инструментов из `providers/`.

**2. Бэкенд в n8n.** Отвечает за факты и правила: какой заказ у этого номера, можно ли ещё поменять адрес, есть ли место в интервале. Агент не знает заказов и не может «придумать» интервал — только спросить у бэкенда.

**3. Таблица заказов.** Google Таблица с листом `Orders`: одна строка — один заказ. Её заполняет ваша система (магазин, CRM, выгрузка), агент меняет только адрес, интервал и отметку о подтверждении и пишет каждое изменение в колонку `history`.

**4. Исходящие звонки.** Воркфлоу Confirmation Calls раз в день выбирает завтрашние заказы без подтверждения и запускает звонок у Vapi или Retell. Разговор ведёт тот же агент с теми же инструментами.

## Почему так

- **Состав заказа агенту недоступен.** Инструмента для него нет: «добавьте пачку», «отмените», «верните деньги» уходят оператору. Модель не может сделать то, на что у неё нет инструмента.
- **Данные заказа — только владельцу.** Адрес и состав видит только номер, на который оформлен заказ. Номер берётся из данных провайдера, а не со слов.
- **Интервалы не переполняются.** У интервала есть `capacity`; заполненный не предлагается, а перед переносом проверяется заново.
- **Поздно — значит оператору.** Когда заказ у курьера или до интервала меньше `change_cutoff_hours`, адрес и время меняет только человек.
- **Одно изменение за запрос.** Единственный узел, который пишет в таблицу, — Sheet Write.
- **Сбой не превращается в ложь.** Если таблица не ответила или устроена не по шаблону, агент получает `tool_unavailable` и не называет выдуманный результат, а операторам приходит сообщение.

## Что входит в набор

| Папка | Что внутри |
|---|---|
| `docs/` | Десять инструкций: от схемы до исходящих звонков |
| `prompts/` | Системный промпт на русском и английском, модули диалога на трёх языках, шаблон базы знаний |
| `providers/` | Конфигурации Vapi, Retell и ElevenLabs |
| `tools/` | Контракт и схемы шести инструментов |
| `workflows/` | Четыре воркфлоу n8n: инструменты заказов, исходящие звонки, сводка звонка, оповещение об ошибках |
| `data/` | Пример настроек и шаблон таблицы заказов |
| `tests/` | 30 тестовых звонков, сценарии проверки бэкенда, готовые запросы, оценочный лист запуска |
| `sales/` | Как продать это клиенту: аргументы, калькулятор, цены, анкета, объём работ, передача, отчёт |
| `samples/` | Примеры разговоров |
