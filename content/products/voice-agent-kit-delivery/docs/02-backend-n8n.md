# Бэкенд в n8n

Нужен n8n с доступом из интернета по https: облачный или свой сервер.

## 1. Таблица заказов

1. Создайте Google Таблицу с листом `Orders`.
2. Импортируйте `data/orders-template.csv`: Файл → Импорт → «Заменить текущий лист». Первая строка — заголовки, их не переименовывайте. Три строки под ними — примеры, удалите их после проверки.
3. Настройте, как туда попадают заказы: выгрузка из магазина, интеграция CRM, ручное заполнение. Нужны `order_id`, `phone`, `customer_name`, адрес, `delivery_date`, `window`, `status`. Остальные колонки заполняет агент.

Порядок колонок неважен — бэкенд ищет их по заголовкам. Если колонки не хватает, агент получит `tool_unavailable`, а операторам придёт сообщение, какой именно.

Не сортируйте и не удаляйте строки в рабочие часы: агент запоминает номер строки на время одного запроса.

## 2. Импорт

1. Workflows → Import from File. Импортируйте четыре файла из `workflows/`:
   - `order-tools.n8n.json`
   - `confirmation-calls.n8n.json`
   - `call-summary.n8n.json`
   - `error-alert.n8n.json`
2. После импорта узлы с учётными данными подсвечены: их нужно выбрать.

## 3. Учётные данные

**Секрет вебхука** — тип Header Auth.
- Name: `X-Voice-Secret`
- Value: случайная строка от 32 знаков. Сгенерировать: `openssl rand -hex 32`.

Выберите его в узлах **Voice Tool Webhook** и **Call Ended Webhook**.

**Google Sheets** — тип Google Sheets OAuth2 API. Войдите под аккаунтом, которому доступна таблица заказов. Выберите в узлах **Sheet Read**, **Sheet Write**, **Read Orders**.

Совет: заведите для автоматизации отдельный аккаунт Google с доступом только к этой таблице.

**Telegram** — тип Telegram API. Создайте бота через @BotFather, вставьте токен. Выберите в узлах **Notify Staff**, **Report**, **Send Summary**, **Send Alert**.

Чтобы узнать chat id: добавьте бота в чат операторов, напишите в чат любое сообщение и откройте `https://api.telegram.org/botТОКЕН/getUpdates` — в ответе будет `chat.id`. Для групп он начинается с минуса.

**Ключ провайдера для исходящих звонков** — тип Header Auth: Name `Authorization`, Value `Bearer ВАШ_КЛЮЧ_API`. Выберите в узле **Start Call**. Подробно — `docs/10-outbound.md`.

## 4. Узел Config

Откройте **Config** в «Order Tools». Это единственное место, где задаются правила. Образец — `data/config.example.json`. Тот же Config есть в «Confirmation Calls» — держите их одинаковыми.

| Поле | Что это |
|---|---|
| `timezone` | Часовой пояс, например `Europe/Kyiv`. От него считается всё время |
| `locale` | Язык, на котором бэкенд произносит даты: `ru-RU`, `uk-UA`, `en-GB` |
| `spreadsheet_id` | ID таблицы из адреса: `docs.google.com/spreadsheets/d/ЭТО_ID/edit` |
| `sheet_name` | Имя листа, по умолчанию `Orders` |
| `staff_chat_id` | Chat id операторов в Telegram |
| `phone` | `country_code` и `national_prefix`: как превращать «050…» в «+38050…» |
| `require_caller_match` | Показывать и менять заказ только с его номера |
| `callback_promise` | Когда свяжется оператор: «в течение часа в рабочее время» |
| `service_cities` | Города зоны доставки — так, как их называют клиенты, со всеми вариантами |
| `delivery_days` | Дни доставки: `mon`…`sun` |
| `closed_dates` | Отдельные дни без доставки |
| `delivery_window_days` | На сколько дней вперёд можно перенести доставку |
| `windows` | Интервалы: `id`, `start`, `end`, `capacity` — сколько заказов везём в этот интервал |
| `change_cutoff_hours` | За сколько часов до начала интервала адрес и время меняет уже только оператор |
| `changeable_statuses` | Статусы, при которых агент может менять адрес и интервал |
| `status_labels` | Как называть статусы клиенту |
| `notify_on_confirm` | Сообщать ли операторам о каждом подтверждении. По умолчанию нет |
| `outbound` | Настройки исходящих звонков — `docs/10-outbound.md` |

`id` интервала в колонке `window` таблицы должен совпадать с `id` в `windows`.

Тот же chat id впишите в узел **Config** воркфлоу «Call Summary» и в узел **Send Alert** воркфлоу «Error Alert».

## 5. Воркфлоу для ошибок

Откройте «Order Tools» → Settings → Error Workflow → выберите «Error Alert». Повторите для «Confirmation Calls» и «Call Summary».

## 6. Включение

Включите «Order Tools», «Call Summary» и «Error Alert». «Confirmation Calls» включите после тестов — `docs/10-outbound.md`. Адреса:

- инструменты: `https://ВАШ-N8N/webhook/voice-tools`
- сводка звонка: `https://ВАШ-N8N/webhook/voice-call-ended`

Используйте адрес Production URL, а не Test URL.

## 7. Проверка без телефона

Выполните запросы из `tests/tool-payloads.md`. Первый же запрос должен найти пример заказа из шаблона. Запрос без секрета должен быть отклонён.

## Данные и журнал

В настройках воркфлоу уже стоит «не сохранять успешные запуски»: в них имена, телефоны и адреса. Ошибочные запуски сохраняются для разбора — ограничьте срок их хранения в настройках n8n.

## Что бэкенд не делает

- Не меняет состав заказа, не отменяет заказ, не оформляет возврат и не меняет оплату.
- Не знает, где курьер, и не называет точное время приезда.
- Не отправляет клиенту SMS. Сообщение можно добавить узлом после **Finish**.
- Не работает напрямую с вашим магазином. Если заказы лежат в другой системе, замените узлы Sheet Read и Sheet Write на её API и приведите ответ к виду строк таблицы с теми же заголовками.
