# Исходящие звонки

Воркфлоу «Confirmation Calls» звонит клиентам накануне доставки и просит подтвердить адрес и интервал. Разговор ведёт тот же агент с теми же инструментами: клиент может подтвердить, поменять адрес или время, попросить оператора.

## Как работает

1. Каждый день в 16:00 (узел **Every Day 16:00**, часовой пояс воркфлоу — `Europe/Kyiv`) читает таблицу заказов.
2. **Pick Calls** выбирает заказы, у которых:
   - доставка завтра;
   - статус из `changeable_statuses`;
   - нет отметки `confirmed`;
   - начатых звонков меньше `outbound.max_attempts`;
   - сегодня ещё не звонили.
   Если сейчас вне окна `call_from`–`call_until`, не звонит никому.
3. **Start Call** запускает звонок у провайдера — по одному каждые три секунды, не больше `max_calls_per_run` за раз.
4. **Mark Calls** записывает в таблицу `calls`, `last_call` и строку в `history`. Звонок, который провайдер не принял, попыткой не считается — но и повторно в тот же день не запускается.
5. **Report** присылает операторам итог: сколько звонков начато и какие не начались.

Агент получает переменные `order_id`, `customer_name`, `delivery` и `address` и начинает разговор с причины звонка — так написано в промпте, раздел «Исходящий звонок».

## Vapi

В Config:

```json
"outbound": {
  "provider": "vapi",
  "vapi_assistant_id": "ID ассистента из панели Vapi",
  "vapi_phone_number_id": "ID номера, с которого звоним"
}
```

Ключ: Dashboard → API Keys → **Private key**. В n8n — учётные данные Header Auth: Name `Authorization`, Value `Bearer ВАШ_КЛЮЧ`.

Запрос, который отправляет воркфлоу: `POST https://api.vapi.ai/call` с полями `assistantId`, `phoneNumberId`, `customer.number`, `customer.name` и `assistantOverrides.variableValues`.

## Retell

```json
"outbound": {
  "provider": "retell",
  "retell_agent_id": "ID агента",
  "retell_from_number": "+380441234567"
}
```

`retell_from_number` — номер, купленный или подключённый в Retell. Ключ API — в Header Auth: Name `Authorization`, Value `Bearer ВАШ_КЛЮЧ`.

Запрос: `POST https://api.retellai.com/v2/create-phone-call` с полями `from_number`, `to_number`, `override_agent_id` и `retell_llm_dynamic_variables`.

## ElevenLabs

Исходящие звонки ElevenLabs запускаются через их интеграцию с Twilio или SIP — этим воркфлоу они не покрыты. Входящие звонки и инструменты работают как обычно.

## Что проверено, а что нет

Воркфлоу запускался в n8n 2.48 против подменного сервера: выбор заказов, запрос к провайдеру с номером клиента и переменными, запись попытки в таблицу и отчёт в Telegram. Тела запросов составлены по документации Vapi и Retell, но с настоящим провайдером мы их не запускали — у API бывают изменения. Перед включением:

1. Поставьте в таблицу один заказ на завтра со своим номером телефона.
2. Откройте воркфлоу и нажмите **Execute workflow** (часы `call_from`–`call_until` должны включать текущее время).
3. Убедитесь, что вам позвонили, агент назвал ваш заказ, а после «да» в таблице появилось `confirmed = да`.
4. Если провайдер ответил ошибкой, она будет в отчёте Telegram и в колонке `history`.

## Правила и вежливость

- Звоните только тем, кто оформил заказ, и только о нём. Сообщите при оформлении, что накануне позвонит виртуальный помощник.
- Проверьте правила своей страны об автоматических звонках: где-то нужно отдельное согласие, где-то ограничены часы.
- `call_from` и `call_until` — не раньше десяти и не позже восьми вечера, если у вас нет причин иначе.
- Больше двух попыток не ставьте: на третий звонок клиенты жалуются.
- Агент спрашивает «Удобно говорить?» и при «нет» вежливо прощается — не уговаривает.

## Включение

Импортированный воркфлоу выключен. Включите его (Publish / Active) после проверки выше. Чтобы звонить в другое время, поменяйте выражение в узле **Every Day 16:00**, например `0 11 * * *` — в 11:00.
