# Контракт инструментов

Шесть инструментов. Один адрес бэкенда для всех: `POST https://ВАШ-N8N/webhook/voice-tools`. Бэкенд сам понимает формат Vapi, Retell и ElevenLabs, входящие и исходящие звонки.

Схемы параметров — в `tools.schema.json`. Здесь — что каждый инструмент делает и что возвращает.

## Общие правила

- Каждый ответ содержит `ok` и поле `say` — подсказку агенту, что делать дальше.
- Ошибка — это `ok: false`, код в `error` и `say`. Агент не зачитывает коды клиенту.
- Запросы без секрета в заголовке отклоняются вебхуком до выполнения.
- За один запрос выполняется один инструмент. Каждое изменение — одна запись в таблицу заказов и строка в колонке `history`.
- **Инструмента для изменения состава заказа, отмены и оплаты нет.** Запрос с неизвестным именем инструмента получает `unknown_tool` и подсказку передать оператору.

## Таблица заказов

Лист `Orders` (имя задаётся в Config). Колонки находятся по заголовкам первой строки, порядок неважен; шаблон — `data/orders-template.csv`.

| Колонка | Что в ней | Кто пишет |
|---|---|---|
| `order_id` | номер заказа | ваша система |
| `phone` | телефон клиента в любом виде | ваша система |
| `customer_name` | имя для приветствия | ваша система |
| `city`, `address`, `apartment`, `entrance`, `floor`, `intercom`, `courier_note` | адрес и подсказки курьеру | ваша система, агент при изменении |
| `delivery_date` | дата доставки, `ГГГГ-ММ-ДД` | ваша система, агент при переносе |
| `window` | `id` интервала из Config, например `12-15` | ваша система, агент при переносе |
| `status` | `new`, `packed`, `out_for_delivery`, `delivered`, `cancelled` | ваша система |
| `items`, `total`, `payment` | состав, сумма, оплата — только для чтения | ваша система |
| `confirmed`, `confirmed_at` | подтвердил ли клиент и когда | агент |
| `calls`, `last_call` | сколько исходящих звонков начато и когда последний | воркфлоу звонков |
| `history` | журнал изменений: что, когда, из какого звонка | агент и воркфлоу звонков |

## Правила изменений

- Номер звонящего должен совпадать с номером заказа (`require_caller_match`). Номер берётся из данных провайдера: при входящем звонке — номер звонящего, при исходящем — номер, на который звоним.
- Адрес (город, улица, дом) и интервал меняются, только пока статус в `changeable_statuses` (по умолчанию `new` и `packed`) и до начала интервала больше `change_cutoff_hours`.
- Квартиру, подъезд, этаж, домофон и подсказку курьеру можно уточнить до доставки, даже когда заказ уже у курьера — оператор получает сообщение и передаёт курьеру.
- Новый город — только из `service_cities`. Новая улица без номера квартиры стирает прежнюю квартиру: у другого дома она другая.
- Интервал заполнен, когда на эту дату и интервал заказов (кроме отменённых) столько же, сколько `capacity`.

## find_order

Вход: `customer_phone`, необязательно `order_id`.

```json
{"ok": true, "orders": [{"order_id": "A-1001", "status": "собран",
  "delivery_date": "2026-10-13", "window_id": "12-15", "delivery": "вторник, 13 октября, с 12:00 до 15:00",
  "address": "Киев, улица Примерная, 5, квартира 12", "items": "Кофемолка", "total": "2400 грн", "payment": "оплачен",
  "confirmed": false, "can_change": true, "change_note": ""}],
 "say": "Назовите клиенту заказ, дату с интервалом и адрес…"}
```

Без `order_id` — до трёх активных заказов номера (не доставленные и не отменённые).

## confirm_delivery

Вход: `order_id`, `customer_phone`, `consent: true`. Пишет `confirmed = да`, время и строку в `history`. Повторное подтверждение ничего не пишет.

## update_address

Вход: `order_id`, `customer_phone`, `consent: true` и хотя бы одно из: `city`, `address`, `apartment`, `entrance`, `floor`, `intercom`, `courier_note`. Город без улицы не принимается. Ответ — новый адрес целиком, как его повторить клиенту. Оператору уходит сообщение «Было / Стало».

## check_windows

Вход: `order_id`, `customer_phone`, `date` (`ГГГГ-ММ-ДД`, `today`, `tomorrow`, `mon`…`sun`, `+N`).

```json
{"ok": true, "available": true, "current": "вторник, 13 октября, с 12:00 до 15:00", "date": "2026-10-14",
 "windows": [{"date": "2026-10-14", "window_id": "09-12", "spoken": "среда, 14 октября, с 09:00 до 12:00"}],
 "say": "Предложите клиенту эти интервалы, не больше двух за раз…"}
```

Если на дату свободных нет — `available: false` и ближайшие интервалы следующих дней. Не предлагаются: дни без доставки (`delivery_days`, `closed_dates`), интервалы ближе `change_cutoff_hours`, заполненные интервалы.

## change_window

Вход: `order_id`, `customer_phone`, `date`, `window_id`, `consent: true`. Перед записью всё проверяется заново; если интервал заполнили — `window_full` и варианты, прежний интервал сохранён. Оператору уходит сообщение «Перенос доставки».

## request_callback

Вход: `customer_name`, `customer_phone`, `topic`, необязательно `order_id`, `urgency`, `details`. Таблицу не читает: отправляет оператору сообщение в Telegram. Через него идут изменения состава, отмена, оплата, жалобы.

## Коды ошибок

| Код | Что значит | Что делает агент |
|---|---|---|
| `missing_fields` | Не хватает данных | Уточняет у клиента и повторяет |
| `no_consent` | Нет подтверждения | Повторяет данные, ждёт «да» |
| `bad_phone` | Номер не распознан | Просит продиктовать по цифрам |
| `caller_mismatch` | Звонят не с номера заказа | Предлагает перезвонить с него или оператора |
| `order_not_found` | Такого заказа на этот номер нет | Вызывает `find_order` |
| `order_closed` | Заказ доставлен или отменён | Объясняет; вопросы — оператору |
| `not_changeable`, `too_late` | Заказ у курьера или до доставки слишком мало времени | Передаёт оператору |
| `outside_zone` | Город вне зоны доставки | Передаёт оператору |
| `bad_date`, `date_in_past`, `too_far`, `closed_date` | Проблема с датой | Уточняет дату |
| `unknown_window`, `window_full`, `too_soon` | Интервал недоступен | Предлагает `windows` |
| `unknown_tool` | Такого действия нет | Передаёт оператору |
| `tool_unavailable` | Таблица не ответила или не по шаблону | Извиняется, не называет результат, оператор |

## Форматы провайдеров

**Vapi** присылает `message.type: "tool-calls"` со списком `toolCallList`; бэкенд отвечает `{"results": [{"toolCallId": "…", "result": "…"}]}`, где `result` — строка с JSON. Номер клиента — `message.call.customer.number`, и при входящем, и при исходящем звонке.

**Retell** присылает `{"name": "…", "args": {…}, "call": {…}}`; номер клиента — `from_number` при входящем и `to_number` при исходящем (`direction: outbound`).

**ElevenLabs** присылает тело из параметров инструмента; имя инструмента передаётся в адресе: `…/webhook/voice-tools?tool=find_order`. Номер клиента — свойство `caller_number`.
