# Как это устроено

```
Гость звонит
     │
Номер телефона ── провайдер голоса (Vapi, Retell или ElevenLabs)
                        │   распознаёт речь, ведёт диалог по промпту, говорит голосом
                        │
                        │  вызов инструмента: «найди стол на четверых в пятницу»
                        ▼
                  n8n: Booking Tools ──────► Google Календарь
                        │                    читает события, создаёт и меняет брони
                        ├──► Telegram администратора: новая бронь, перенос, отмена, банкет, просьба перезвонить
                        ▼
                  ответ агенту: варианты времени или результат

После звонка: провайдер ──► n8n: Call Summary ──► Telegram: сводка звонка
При сбое:     n8n: Error Alert ──► Telegram: что сломалось
```

## Три части

**1. Провайдер голоса.** Отвечает за разговор: слышит, понимает, говорит. Вы даёте ему промпт из `prompts/` и шесть инструментов из `providers/`.

**2. Бэкенд в n8n.** Отвечает за факты: есть ли свободный стол на эту компанию, создана ли бронь. Агент не знает рассадки и не может «придумать» свободный стол — только спросить у бэкенда.

**3. Календарь.** Одно расписание на ресторан. Каждая бронь — событие «Бронь: 4 гост. — Имя», в котором скрыто записаны телефон гостя, число гостей и стол. Хостес видит брони на день в обычном Google Календаре.

## Почему так

- **Агент не называет время по памяти.** Свободные столы считает программа по календарю. Это убирает главную ошибку голосовых агентов — бронь на занятое время.
- **Дату считает бэкенд.** Агент передаёт «tomorrow» или «fri», бэкенд возвращает дату и то, как её произнести. Модели ошибаются в днях недели; программа — нет.
- **Стол подбирается по компании.** Пара получает стол на двоих, компания на шестерых — большой стол; сколько держим стол, тоже зависит от числа гостей.
- **Одно изменение за запрос.** Единственный узел, который что-то пишет в календарь, — Calendar Write. Его легко найти и проверить.
- **Повтор не создаёт дубль.** Провайдеры повторяют запрос при таймауте. Идентификатор брони выводится из звонка и времени, поэтому вторая бронь не появится.
- **Сбой не превращается в ложь.** Если календарь не ответил, агент получает `tool_unavailable` и предлагает обратный звонок, а администратору приходит сообщение.
- **Чужую бронь не отменить.** Перенос и отмена работают только с номера, на который оформлена бронь.
- **Банкеты — людям.** Компанию больше `max_guests` агент не бронирует, а передаёт менеджеру.

## Как один календарь вмещает все столы

В событии хранится `staff_id` — идентификатор стола. Время свободно для компании, если свободен хотя бы один подходящий ей стол. Событие, созданное вручную без `staff_id` — банкет, закрытие на мероприятие, санитарный день, — закрывает ресторан целиком. Чтобы убрать из продажи один стол, создайте бронь на него; подробнее — в `docs/08-operations.md`.

Чего календарь не знает: кто пришёл без брони. Если зал заполняют гости с улицы, держите часть столов вне `tables` в Config — агент их не продаст.

## Что входит в набор

| Папка | Что внутри |
|---|---|
| `docs/` | Девять инструкций: от схемы до настройки по записям звонков |
| `prompts/` | Системный промпт на русском и английском, модули диалога на трёх языках, шаблон базы знаний |
| `providers/` | Конфигурации Vapi, Retell и ElevenLabs |
| `tools/` | Контракт и схемы шести инструментов |
| `workflows/` | Три воркфлоу n8n: бронирование, сводка звонка, оповещение об ошибках |
| `data/` | Пример настроек: часы, столы, зоны, сколько держим стол |
| `tests/` | 30 тестовых звонков, сценарии проверки бэкенда, готовые запросы, оценочный лист запуска |
| `sales/` | Как продать это клиенту: аргументы, калькулятор, цены, анкета, объём работ, передача, отчёт |
| `samples/` | Примеры разговоров |
