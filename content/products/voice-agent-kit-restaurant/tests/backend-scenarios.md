# Проверка бэкенда

Бэкенд бронирования — тот же, что в остальных наших голосовых наборах, с изменениями для ресторана: бронируется стол, а не услуга, и число гостей решает, какие столы подходят и сколько стол держится. Общая часть проверена 20 сценариями в тестах тех наборов. Изменения для ресторана проверены отдельно: 16 тестами узлов Code на подменном календаре и запуском в n8n 2.48 с запросами в форматах Vapi, Retell и ElevenLabs.

Что это значит для вас: узлы Code можно не читать, но если вы их меняете — повторите проверки из `tool-payloads.md`.

Чего проверка не покрывает: работу с настоящим Google Календарём под вашими учётными данными и качество распознавания речи. Это проверяется запросами из `tool-payloads.md` и звонками из `test-calls.md`.

## Сценарии для ресторана

1. Паре предлагается самый маленький подходящий стол, с открытия, а последний вариант заканчивается к закрытию.
2. Компании на троих достаётся стол на четверых, на шестерых — большой стол; стол с минимальным числом гостей не отдаётся паре.
3. Зона «терраса» сужает выбор до столов на террасе.
4. Компания больше `max_guests`, ноль или «двое» словами, неизвестная зона, зона без подходящего стола и неполный запрос отклоняются без обращения к календарю.
5. Столы заполняются по одному, от маленьких к большим; когда подходящих не осталось — отказ с вариантами другого времени.
6. После ухода гостей стол свободен только через `buffer_min`.
7. Бронь записывается с числом гостей, поводом и пожеланиями; стол держится столько, сколько задано в `durations`.
8. Повтор того же запроса возвращает ту же бронь, вторая не создаётся.
9. Бронь без «да», стол, который не подходит компании, и время, когда стол не успеют освободить до закрытия, отклоняются.
10. Если компания выросла, перенос с новым числом гостей пересаживает её за подходящий стол и продлевает время; слишком большая компания — отказ.
11. Изменить бронь можно только с её номера; поздняя отмена отмечается.
12. Событие в календаре без стола (банкет, закрытие) закрывает ресторан на это время.
13. Просьба перезвонить уходит администратору; при отказе календаря агент не получает выдуманного результата.
14. Форматы Retell и ElevenLabs распознаются, число гостей принимается и строкой.

## Запуск в n8n

Воркфлоу импортирован в n8n 2.48 вместе с подменными Google Календарём и Telegram. Проверено: неверный секрет отклоняется; паре предлагается стол у окна; бронь на четверых пишется в календарь с числом гостей и поводом, администратору приходит сообщение; повтор не создаёт вторую бронь; компания на двенадцать — отказ без обращения к календарю; поиск через Retell, свободное время через ElevenLabs; отмена с чужого номера — отказ; перенос с ростом компании до шести — большой стол; отмена; отказ календаря — `tool_unavailable` и сообщение о сбое.
