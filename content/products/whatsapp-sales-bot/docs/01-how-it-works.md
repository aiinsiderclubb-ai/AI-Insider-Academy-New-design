# Как это работает

## Схема

```
Клиент пишет в WhatsApp
  → Meta отправляет вебхук → n8n сразу отвечает 200
  → проверка подписи X-Hub-Signature-256 секретом приложения
  → сообщение отмечается прочитанным
  → карточка клиента и каталог читаются из Google Таблицы
  → решение:
       «стоп»            → подтверждение отписки, бот молчит
       отписан           → тишина (пока клиент не напишет «старт»)
       ведёт менеджер    → тишина, сообщение пересылается в чат менеджеров
       просит человека   → «передаю менеджеру» + сообщение в чат
       остальное         → модель: ответ, поля, стадия, кнопки
  → ответ в WhatsApp (текст или кнопки)
  → карточка клиента обновляется в таблице
  → горячий клиент или нужен человек → карточка в Telegram с кнопками
```

## Карточка клиента — лист Contacts

Одна строка на номер. Заголовки пишутся при первой записи.

| Колонка | Что это |
|---|---|
| `wa_id` | Номер в формате WhatsApp, без плюса |
| `name` | Имя из профиля WhatsApp |
| `phone` | Номер с плюсом |
| `first_seen` | Первое сообщение |
| `last_in_at` / `last_out_at` | Последнее сообщение клиента / последний ответ ему |
| `status` | `bot` — отвечает бот; `manager` — ведёт менеджер; `opted_out` — отписался |
| `stage` | `new`, `qualifying`, `qualified`, `hot`, `not_fit`, `support` |
| `need`, `budget`, `timeline` | Поля квалификации — названия задаются в Config (`qualify`) |
| `details` | Свободная колонка для ваших заметок |
| `hot` | `yes`, если клиент дошёл до горячей стадии (команда получает сообщение один раз) |
| `handoff_until` | До какого времени бот молчит, если клиента ведёт менеджер |
| `followup_sent` | `yes`, если напоминание уже отправлено |
| `history` | Последние ~3500 символов переписки |
| `manager` | Кто из менеджеров ведёт клиента |
| `notes` | Свободная колонка |

Ваши колонки добавляйте правее `notes` — бот их не трогает. Не переставляйте и не удаляйте колонки A–R.

## Когда бот передаёт клиента человеку

- Клиент готов к следующему шагу (модель ставит `hot`) — один раз за клиента.
- Клиент просит менеджера: слова из `human_words` (с окончаниями: «менеджера», «оператору»).
- Модель решила, что нужен человек: жалоба, нестандартный заказ, раздражение.
- Модель не ответила или ответила не JSON.

После передачи бот молчит `handoff_hours` часов. Новые сообщения клиента пересылаются в чат менеджеров. Кнопка «Вернуть боту» снимает передачу раньше; по истечении срока бот снова отвечает сам.

## Окно 24 часа

WhatsApp разрешает свободные сообщения клиенту только в течение 24 часов после его последнего сообщения. Позже — только одобренные шаблоны. Поэтому:

- напоминание отправляется не позже чем через 23,5 часа;
- ответ менеджера из Telegram позже 24 часов не отправляется: в чат приходит объяснение и номер — позвоните или используйте шаблон из инструмента рассылок;
- если WhatsApp всё же отказал в доставке, команда получает сообщение с текстом, который не дошёл.

## Узлы «Bot»

| Узел | Что делает |
|---|---|
| Verify Webhook | Разовая проверка адреса при сохранении вебхука в Meta (GET) |
| WhatsApp Webhook → Respond OK | Принимает события и сразу отвечает 200, чтобы Meta не повторяла запрос |
| Sign Body | Считает HMAC-SHA256 тела запроса секретом приложения |
| Config | Все настройки |
| Inbound | Сверяет подпись, отбрасывает статусы доставки, чужие номера и старые повторы, достаёт текст (кнопки, подписи к фото) |
| Mark Read | Синие галочки у клиента |
| Read Contacts and Catalog | Одно чтение двух листов |
| Converse | Отписка, передача, запрос к модели |
| Ask AI | Модель |
| Reply | Разбирает ответ модели, готовит сообщение, запись в таблицу и карточку для менеджеров |
| Send WhatsApp | Отправка через Graph API |
| Not Delivered / Sheet Unavailable | Сообщают команде, если доставка или таблица не сработали |
