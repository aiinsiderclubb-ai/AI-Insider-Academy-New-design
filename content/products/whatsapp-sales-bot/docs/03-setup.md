# Установка

## Импорт

1. В n8n: Workflows → Import from File. Импортируйте файлы по одному:
   - `workflows/whatsapp-bot.n8n.json` — вебхук WhatsApp: проверка подписи, ответ консультанта, запись в таблицу, передача менеджерам
   - `workflows/whatsapp-manager-replies.n8n.json` — менеджеры отвечают клиентам из Telegram, кнопки «Беру» и «Вернуть боту»
   - `workflows/whatsapp-followup.n8n.json` — одно напоминание замолчавшему клиенту в пределах 24 часов
   - `workflows/whatsapp-daily-report.n8n.json` — утренний отчёт и список горячих клиентов
   - `workflows/error-alert.n8n.json` — сообщение в Telegram о любом сбое
2. После импорта узлы, которым нужны учётные данные, подсвечены красным — их нужно выбрать (раздел ниже).
3. Откройте каждый воркфлоу → Settings → Error Workflow → выберите «Error Alert». Без этого о сбое вы узнаете от клиента.
4. Включите воркфлоу переключателем Active (Publish) вверху справа. Используйте Production URL, а не Test URL.

Воркфлоу проверены на n8n 2.44. На более старых версиях узлы могут называться иначе; обновите n8n, если импорт показывает неизвестные узлы.

## Учётные данные

Создайте в n8n (Credentials → Add credential) и выберите в подсвеченных узлах.

**Google Sheets** — тип Google Sheets OAuth2 API.
Войдите под аккаунтом, у которого есть доступ к таблице. Совет: отдельный аккаунт Google для автоматизации с доступом только к нужным таблицам.

**WhatsApp** — тип Header Auth.
- Name: `Authorization`
- Value: `Bearer постоянный-токен`

Постоянный токен выдаётся системному пользователю в Meta Business Settings → Users → System users → Generate token, с разрешениями `whatsapp_business_messaging` и `whatsapp_business_management`. Временный токен из панели разработчика живёт сутки — для работы не подходит.

**Telegram** — тип Telegram API.
Создайте бота через @BotFather (`/newbot`), вставьте токен. Добавьте бота в чат, куда должны приходить сообщения. Чтобы узнать chat id: напишите в чат любое сообщение и откройте `https://api.telegram.org/botТОКЕН/getUpdates` — в ответе будет `chat.id`. У групп он начинается с минуса.

**Ключ модели** — тип Header Auth.
- Name: `Authorization`
- Value: `Bearer ваш-ключ`

Подходит любой сервис с OpenAI-совместимым API: OpenAI, OpenRouter (через него доступны модели Anthropic, Google и другие), Groq, Together, локальный сервер. Адрес и модель задаются в узле Config: `llm.base_url` и `llm.model`.


**App Secret** — тип Crypto. В поле Hmac Secret вставьте App Secret приложения Meta. Используется узлом **Sign Body** для проверки подписи. Без него любой, кто знает адрес вебхука, мог бы писать от имени клиентов.

## Бот в чате менеджеров

Режим приватности бота (по умолчанию включён) не мешает: бот получает нажатия кнопок и ответы на свои сообщения — этого достаточно. Сообщения из других чатов «Manager Replies» игнорирует.

У одного Telegram-бота может быть только один вебхук. Если ваш бот уже принимает сообщения в другом воркфлоу n8n (например, в наборе поддержки), создайте для этого набора отдельного бота.

## Узел Config в «Bot»

| Поле | Что это |
|---|---|
| `spreadsheet_id` | Идентификатор таблицы — часть адреса между `/d/` и `/edit` |
| `contacts_sheet` | Лист карточек клиентов. По умолчанию `Contacts` |
| `catalog_sheet` | Лист каталога: товар, цена, описание. По умолчанию `Catalog` |
| `catalog_max_chars` | Сколько символов каталога отправлять модели |
| `graph_api_base` | Адрес Graph API с версией |
| `phone_number_id` | Phone number ID из Meta (не сам номер) |
| `verify_token` | Ваша случайная строка для проверки вебхука |
| `verify_signature` | Проверять подпись Meta. Не выключайте в работе |
| `max_message_age_minutes` | Сообщения старше — повторы Meta, они не обрабатываются |
| `team_chat_id` | Чат менеджеров в Telegram |
| `handoff_hours` | Сколько часов бот молчит после передачи клиента менеджеру |
| `llm` | Адрес API, модель, режим JSON. `enabled: false` — без модели: каждое сообщение уходит менеджерам |
| `business` | Название, чем занимаетесь, что предлагаете, следующий шаг для готового клиента, тон |
| `qualify` | Что выяснить у клиента: `key` — колонка в таблице, `label` — как это объяснить модели. Ключи `need`, `budget`, `timeline` уже есть в таблице; свои ключи добавляйте вместо них, а не сверх |
| `opt_out_words / opt_in_words` | Слова отписки и возврата — только целым сообщением или словом |
| `human_words` | Слова, по которым клиент сразу уходит к менеджеру. Окончания учитываются |
| `texts` | Готовые ответы: отписка, возврат, передача менеджеру, ответ при сбое модели |
| `followup` | Напоминание: включено, через сколько часов тишины, текст. `{name}` — имя клиента |
| `working_hours` | Когда можно отправлять напоминания |
| `max_reply_chars` | Предел длины ответа бота |
| `report_chat_id` | Куда слать утренний отчёт. Пусто — в чат менеджеров |

Пример заполненного Config — `templates/config.example.json`.

## Остальные воркфлоу

В «Manager Replies», «Follow-up» и «Daily Report» — короткий Config с теми же значениями: таблица, лист, Phone number ID, chat id, часовой пояс. Заполните одинаково с «Bot».

Время отчёта — узел **Every Morning**; проверка напоминаний — узел **Every Hour**.

## Какую модель выбрать

Задачи в этих воркфлоу — классификация и короткие ответы. Большая модель не нужна: берите быструю и недорогую модель среднего класса у любого провайдера. Проверьте на 20 реальных примерах, прежде чем включать.

- Модель должна уметь отвечать в формате JSON. Если провайдер не поддерживает режим JSON, поставьте `llm.json_mode: false` — воркфлоу всё равно найдёт JSON в ответе.
- Температура зафиксирована на 0: одинаковые входные данные дают одинаковый результат.
- Стоимость: один вызов — это несколько сотен входных токенов и до сотни выходных. Цены смотрите у провайдера; на сотни обращений в месяц это обычно единицы долларов.
- Что уходит провайдеру модели: текст обращения и контекст из Config. Если в обращениях бывают чувствительные данные, выберите провайдера с подходящими условиями хранения или выключите модель (`llm.enabled: false`) — тогда работают правила.

## Если что-то не работает

| Что видите | Где смотреть | Частая причина |
|---|---|---|
| Ничего не приходит | n8n → Executions | Воркфлоу не включён или используется Test URL вместо Production URL |
| Ошибка 401 или 403 у Google | Учётные данные Google | Истёк доступ — переподключите учётные данные |
| Ошибка 400 у Google: Unable to parse range | Config → `sheet_name` | Лист с таким названием не создан |
| Сообщения не приходят в Telegram | Чат | Бот не добавлен в чат или неверный chat id |
| Ошибка 401 у модели | Учётные данные модели | Неверный ключ или нет слова `Bearer ` перед ним |
| Модель отвечает, но оценки странные | Config → описание бизнеса | Слишком общее описание: опишите, кто идеальный клиент |
| Meta не сохраняет вебхук | Config → `verify_token`, воркфлоу «Bot» | Токены не совпадают или воркфлоу не включён |
| Сообщения приходят, бот молчит, в Executions нет запусков дальше Inbound | Учётные данные App Secret | Неверный App Secret — подпись не сходится |
| Ошибка 401 у WhatsApp | Учётные данные WhatsApp | Временный токен истёк — нужен постоянный токен системного пользователя |
| Ошибка 131047 | Сообщение «не доставлено» в чате | Прошло больше 24 часов — нужен шаблон |
| Ошибка 131030 | Тестовый номер Meta | Номер получателя не добавлен в список разрешённых |
