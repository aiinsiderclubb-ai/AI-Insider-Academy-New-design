# Мониторинг и поддержка

## n8n Monitor

Воркфлоу **n8n Monitor** раз в час через API n8n:

- присылает новые ошибки с прошлой проверки — по одному сообщению на воркфлоу, со ссылкой на запуск;
- сообщает, если воркфлоу из `must_be_active` выключен (руками или самим n8n после ошибок триггера), и ещё раз — когда его включат;
- в `digest_hour` присылает сводку за сутки.

Настройка:

1. В n8n клиента: Settings → n8n API → Create an API key.
2. В n8n, где работает монитор: учётные данные Header Auth, Name `X-N8N-API-KEY`, Value — ключ.
3. Config: `n8n_api_base` (`https://n8n-клиента/api/v1`), `n8n_url` для ссылок, `alert_chat_id`, `must_be_active` — id важных воркфлоу (видны в адресе воркфлоу).

Монитор может работать на вашем n8n и следить за несколькими клиентами — по копии на клиента.

## Если упал сам n8n

Монитор внутри n8n не сообщит о том, что n8n недоступен. Добавьте внешнюю проверку: любой сервис мониторинга доступности (UptimeRobot, Better Stack и т. п.) на адрес `https://n8n-клиента/healthz` раз в 5 минут с уведомлением вам в Telegram или на почту.

## Что входит в поддержку

`sales/maintenance-offer.md` — три уровня. Обычно:

- мониторинг и реакция на сбои в оговорённое время;
- обновления n8n раз в месяц (сначала на копии);
- резервные копии воркфлоу и учётных данных;
- ежемесячный отчёт: запуски, ошибки, что исправлено, что предлагаем улучшить;
- часы на доработки.

## Ежемесячный отчёт клиенту

1. Сколько автоматизаций работает, сколько ошибок, сколько из них исправлено и за сколько.
2. Экономия к прошлому тарифу Zapier/Make — `sales/roi-calculator.csv`.
3. Что изменилось в бизнесе клиента и что стоит автоматизировать дальше — источник новых проектов.

## Импорт

1. В n8n: Workflows → Import from File. Импортируйте файлы по одному:
   - `workflows/n8n-monitor.n8n.json` — ошибки, выключенные воркфлоу и утренняя сводка по n8n клиента
   - `workflows/parallel-run-log.n8n.json` — приём итогов от старой системы и n8n, сравнение, сигнал о расхождении
   - `workflows/parallel-run-check.n8n.json` — события, потерянные одной стороной, и ежедневная готовность к переключению
   - `workflows/error-alert.n8n.json` — сообщение в Telegram о любом сбое
2. После импорта узлы, которым нужны учётные данные, подсвечены красным — их нужно выбрать (раздел ниже).
3. Откройте каждый воркфлоу → Settings → Error Workflow → выберите «Error Alert». Без этого о сбое вы узнаете от клиента.
4. Включите воркфлоу переключателем Active (Publish) вверху справа. Используйте Production URL, а не Test URL.

Воркфлоу проверены на n8n 2.44. На более старых версиях узлы могут называться иначе; обновите n8n, если импорт показывает неизвестные узлы.

## Учётные данные

Создайте в n8n (Credentials → Add credential) и выберите в подсвеченных узлах.

**Google Sheets** — тип Google Sheets OAuth2 API.
Войдите под аккаунтом, у которого есть доступ к таблице. Совет: отдельный аккаунт Google для автоматизации с доступом только к нужным таблицам.

**Telegram** — тип Telegram API.
Создайте бота через @BotFather (`/newbot`), вставьте токен. Добавьте бота в чат, куда должны приходить сообщения. Чтобы узнать chat id: напишите в чат любое сообщение и откройте `https://api.telegram.org/botТОКЕН/getUpdates` — в ответе будет `chat.id`. У групп он начинается с минуса.

**Ключ API n8n** — тип Header Auth: Name `X-N8N-API-KEY`, Value — ключ из Settings → n8n API.
