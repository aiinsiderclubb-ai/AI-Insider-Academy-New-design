# Как проверено

## Инструмент аудита

- Blueprint Make: линейный сценарий с вебхуком и сценарий с Iterator, Aggregator и Router на две ветки.
- Экспорт Zapier: три zap'а с Formatter, Filter, Paths, Storage, Code, Digest, Email by Zapier.
- Ручная опись CSV: три автоматизации с числом запусков.
- Результат: 8 автоматизаций, волны, риски, доступы без внутренних инструментов платформ, оценка в часах и деньгах — `tools/example-output/`.

## Логика узлов Code — 4 сценария

1. Монитор: новые ошибки сгруппированы по воркфлоу со ссылкой на запуск, собственный воркфлоу монитора исключён, старые ошибки не повторяются, выключенный воркфлоу — одно сообщение и «снова работает» при включении.
2. Сводка — раз в сутки в заданный час.
3. Сверка: без токена — 403, неверная система — 422; одинаковые после нормализации результаты (регистр почты, «10.0» и 10, игнорируемые поля) — совпадение; расхождение во вложенном поле — одно сообщение.
4. Проверка: событие только от одной стороны дольше `wait_minutes` — `missing` и сообщение; утренний отчёт по потокам с готовностью к переключению.

## Запуск в n8n 2.44

Воркфлоу импортированы в n8n; расписания запускались вручную. API n8n, Google Таблицы и Telegram заменены локальным сервером с теми же форматами.

- Монитор через подменный API n8n → сообщение об ошибках со ссылкой и о выключенном воркфлоу.
- Сверка по HTTP: 403, 422, совпадение, расхождение с сообщением, строки в таблице.
- Проверка по расписанию → событие от одной стороны помечено `missing`, сообщение в Telegram.

## Что не проверялось

- Настоящий экспорт Zapier с вашего тарифа: формат меняется, при ошибке используйте опись CSV.
- API n8n клиента и настоящие Telegram и Google Таблицы.
- Сохранение памяти монитора между запусками работает только при запуске по расписанию.
